# NoteFlow 编辑器可靠性与迁移评估

日期：2026-07-15  
结论：Markdown 继续作为服务端唯一正文格式；Tiptap 3（基于 ProseMirror）是唯一编辑器，经典编辑器及兼容回退已删除。

## 1. 已删除经典编辑器的风险记录

已删除的经典链路为：

```text
Markdown → Marked → 增强 HTML → 原生 contentEditable → Turndown → Markdown
```

优点：依赖少、渲染快、现有代码块和 Markdown 样式可继续使用。

主要风险：

1. 选区格式依赖 `document.execCommand`，浏览器行为难以精确测试和控制。
2. DOM 是编辑时事实来源，粘贴、嵌套格式和浏览器自动修复标签后可能产生不同结构。
3. 撤销历史由浏览器管理，外部重渲染、AI 替换和正文同步容易打断历史栈。
4. 光标与选区使用 DOM Range，AI 修改前后难以稳定映射。
5. 表格原先没有 Turndown 规则，编辑保存后会退化为普通文本。本轮已增加 GFM 表格序列化。
6. 合并单元格、复杂 HTML、自定义块仍无法无损映射到标准 Markdown。

## 3. 候选方案对比

### Tiptap 3 + `@tiptap/markdown`

官方 Markdown 扩展支持 Markdown 初始化、`getMarkdown()`、按光标或 Range 插入 Markdown，并能通过扩展定义自定义解析和序列化；GFM 表格和任务列表需要同时注册对应扩展。当前官方仍将 Markdown 包标为 Beta，因此必须用 NoteFlow 自己的保真夹具作为升级门禁。[Tiptap Markdown 基础用法](https://tiptap.dev/docs/editor/markdown/getting-started/basic-usage) [Tiptap Editor Markdown API](https://tiptap.dev/docs/editor/markdown/api/editor)

优点：

1. React 集成成熟，工具栏、Bubble Menu 和扩展生态适合现有界面。
2. 底层 ProseMirror 具有 Schema、Selection、Transaction 和 History。
3. `insertContentAt({ from, to })` 适合把 AI 修改落到明确选区。
4. 可为 NoteFlow 的 `<u>`、`<mark>`、文本样式和未来 Callout 编写双向 Markdown 扩展。

风险：

1. Markdown 包仍为 Beta。
2. Schema 未声明的 HTML/属性会被移除，因此必须先补齐所有 NoteFlow 节点和 Mark。[Tiptap Schema](https://tiptap.dev/docs/editor/core-concepts/schema)
3. 初次引入会增加包体和编辑器适配代码。

### 直接使用 ProseMirror

ProseMirror 把文档、选区和插件状态放在不可变 EditorState 中，所有修改通过 Transaction 进入统一更新点；History 插件基于 Transaction 实现撤销重做。[ProseMirror Guide](https://prosemirror.net/docs/guide/)

优点是控制力最高、AI 修改与选区映射最可靠；缺点是需要自行搭建 React 绑定、菜单、节点视图、粘贴规则和 Markdown 适配，开发量明显高于 Tiptap。

### Lexical

Lexical 使用包含节点树和选区的可序列化 EditorState，Markdown 包提供导入、导出、快捷输入和可配置 Transformer。[Lexical Editor State](https://lexical.dev/docs/concepts/editor-state) [Lexical Markdown](https://lexical.dev/docs/packages/lexical-markdown)

优点是 React 友好、状态模型清晰、性能好；缺点是 NoteFlow 仍需自行补齐 Markdown Transformer、表格/代码交互和现有工具栏适配。与已经采用 Marked、且需要自定义 Markdown 双向扩展的 Tiptap 3 相比，没有形成足够迁移优势。

## 4. 选型结论

选择 Tiptap 3，保留 Markdown 为数据库和 API 的唯一正文格式。

不把 Tiptap JSON 直接写入现有 `notes.content`，原因：

1. 现有 RAG、版本、导出、AI 草稿和修改预览均以 Markdown 为契约。
2. 改为 JSON 会同时扩大后端解析、索引和历史数据迁移范围。
3. Markdown 更适合用户导出和长期可迁移性。

Tiptap JSON 只作为编辑器运行时状态；保存时必须通过统一 Codec 输出 Markdown。

