# 章节编号：结构派生与旧格式兼容

2026-10-21 修订。此前 `a128e06` 的“先建立所有写入校验、格式版本和全库迁移”是未实施提案，不再作为本次改进的前置条件。当前选择复用 Tiptap 的标题结构，在编辑器解析、显示和序列化之间建立兼容层，不批量改写用户笔记。

状态：核心逻辑、真实编辑器单测与本轮隔离浏览器回归已完成；已在当前应用只读核对桌面和 320px 阅读 / 目录。真实模型到生产写入、实体设备与其他浏览器未验收，不宣称所有历史内容和任意序号歧义都已解决。

## 参考与取舍

- [Notion 官方页面排版说明](https://www.notion.com/help/columns-headings-and-dividers)：目录读取实际标题，按标题级别缩进。实际检查用户授权打开的 GORM 页面，`0.`、`4.1` 已在可编辑标题文字中，不能把这页当成“Notion 会自动管理章节编号”的证据。
- [Word 官方多级标题编号](https://support.microsoft.com/en-us/word/number-your-headings)：编号方案关联标题样式。借鉴的是结构与编号格式分工，不引入完整 Word 设置界面。
- [Typora 官方自动编号示例](https://support.typora.io/Auto-Numbering/)：CSS counter 派生显示，但仅复制 CSS 不足以解决旧前缀、复制和导出的一致性。

以下为 NoteFlow 的实现决策，不宣称是上述产品的内部架构。

## 三份职责，不是三份大纲

1. 标题节点维护实际 `level` 和可编辑标题文字。层级来自 Markdown / 编辑器结构，不根据 `一、`、`9.7` 等字符猜测。
2. `numberHeadings` 仅按结构与顺序计数：`1.`、`1.1`、`1.1.1`。支持编辑器 H1–H6；此前只编号两层会使更深旧序号无接替，所以本轮统一递进。重排、插入、删除、改变标题级别都重新派生，没有开关。
3. 正文 Decoration、桌面 / 手机目录与复制使用同一结果。匹配文件名的首块无手写序号 H1 是文档主标题，不参与章节计数；其他 H1 不凭“第一个”就被删除或降级。空标题不计数、不加入目录。

## 旧格式兼容：不是打开即迁移

`editor/structuredHeading.ts` 将已知旧前缀从可编辑字符中解析成节点的 `sourcePrefix` 兼容属性，并保留原来的粗体等标记。正文中没有 `display:none` 的可编辑序号，也不对旧标题再叠一套数字。

普通 Markdown 序列化将兼容属性还原为原来的前缀，避免只打开笔记就重写内容、改变保存基准或使待确认 AI 预览的源哈希失效。该属性不输出到 HTML。新 AI 标题继续沿用已实施的无手写序号提示和结果处理。

- 普通加载、导入后的打开、版本恢复后的打开、AI 结果进入同一富文本编辑器，使用相同解析器；不需要用户逐篇点击“统一编号”，正常界面已移除该动作。
- 粘贴 / 编辑中完成的前缀，在同一编辑事务链转成兼容属性；移动光标不扫描。只检查变更附近节点，输入法组合中不转换，组合结束后再检查。
- PM 中段拆分标题会复制属性；识别实际的空双包装 split step，清除新半段的旧序号属性。新标题、空标题、撤销 / 重做都有回归，删除全部标题文字不能在重开时复活孤立序号。
- 后端索引标题仍可能带旧前缀，定位 / 当前章节匹配采用同一前缀识别；不改索引表或服务端原件。
- 阅读高亮与光标追踪使用同一份排除文档主标题的章节结果，避免目录里没有的主标题占据活动位置。标题上下文初始化相同则不发事务，重命名的纯显示事务不进入保存或撤销历史，避免代码结尾文档的 trailing-node 工作误触保存。
- 整篇 AI 预览接收相同文档名上下文，小节 / 选区预览不把首个 H1 冒充文档名。对照插件原先在关闭状态也发空 Decoration 事务，会对代码结尾稿件触发 trailing-node 和手动保存；现在空状态不派发，开合对照的显示事务禁止更新通知，不自动保存稿件。
- 原 `normalizeHeadingNumbers` 仅保留为可撤销的显式维护函数，不由打开、保存或普通 UI 自动调用。

这不是声称全库已转换为“无前缀 Markdown”。服务器普通写入、草稿保存、AI 应用、版本恢复没有改为新的拒绝 / 重写接口，也没有执行格式版本迁移。

## 复制与导出

- 复制完整标题带当前结构编号，部分选字不插入章节号。只改变剪贴板切片，不改变原文、选区或历史。
- Markdown ZIP 导出在副本中替换旧序号，保留其余源格式、代码、CRLF 和支持的行内标记；全前缀被消费时清理空粗体 / 链接包装，避免 `****` 变成分隔线。导入后再导出不叠号。
- 无法精确映射的特殊 Markdown / HTML，整篇保留原文，不猜位置；这类回退不能声称与显示完全统一。
- JSON 备份仍保留原始源内容。没有写库、补建历史版本或触发批量索引。
