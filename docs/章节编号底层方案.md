## 用户应当得到的结果

- 任意笔记使用同一套章节规则，不需要逐篇点击「统一编号」。
- 文档名 / 正文中的文档主标题不编号；章节为 `1.`、`2.`，子章节为 `1.1`、`1.2`。深级标题默认仅用字号 / 间距区分，暂不扩展本轮既定的两级自动编号范围。
- 插入、删除、重排章节或改变标题级别后，显示编号随文档结构更新。
- 正文、桌面 / 手机目录、复制与导出消费同一个结构结果。

## 已确认的问题

`4e0c970` 只识别旧序号、不清理旧内容；`f1e6794` 加了显式整理动作。它们可以补救旧笔记，却没有建立所有入口必须遵守的契约。

1. `src/utils/headingNumbering.ts` 仍使用手写数字影响计数和 hierarchyDepth，包括兼容旧平级十进制标题的分支。标题文字与结构同时在决定编号。
2. `server/app/services/heading_numbers.py` 仅用于部分草稿处理，普通创建 / 保存、应用 AI 修改、恢复版本各自写入 `Note.content`。
3. 前端编辑器的真实内容和保存回包必须一致。`store/index.tsx::persistNoteContent` 会把成功回包的正文放回 fileContents，`NoteEditor` 发现内容不同会 setContent。仅在后端静默清洗会重建当前文档，影响光标、选字、撤销和正在生成的选区快照。
4. AI 修改预览用原文哈希限制应用范围，离线保存也保留基准哈希。迁移若绕过这些保护，会把格式升级变成同步冲突或使待确认修改失效。

## 内容契约

继续保存 Markdown。标准章节标题只保存标题文字与 Markdown 级别：

```markdown
## Docker 是什么
### 一句话定义
## 安装 Docker
### 环境准备
```

显示编号是结构的派生结果，不是可被 AI、导入器、用户输入和后端分别维护的标题字符。文件名不参加章节计数。正文首个 H1 与文档名一致时沿用现有「正文主标题」识别，保留该 H1，但从章节编号中排除；其他 H1 不能仅凭“第一个”就删除或降级。

规范编号仅依赖文档结构及顺序。手写 `一、`、`1.`、`1.1` 不再修改规范结构的计数器。旧平级标题却用 `2.1` 表达子节的情况属于结构歧义，升级时单独报告，不根据字符猜测并修改标题级别。

旧序号识别是入口转换规则，不是规范编号算法。明确的中文章号 / 括号、上下级连续序号可以转换；年份、版本、数学常量、专有名词、没有实际标题的空序号保留。不能只靠一个宽泛正则删除所有开头数字。

JS / Python 通过一份版本化策略与共享输入输出用例约束实现：序号前缀、文档标题角色、两级编号、歧义保留和受保护语法。用真实 Markdown 结构确定标题，围栏 / 缩进代码、行内代码、普通列表、正文、表格和代码注释不参加标题转换。不能把正则扫描到的 `#` 都当作标题。

## 入口与写入职责

| 入口 | 应执行的处理 |
| --- | --- |
| AI 生成大纲 / 正文 | 提示要求无手写序号；模型结果进入草稿前执行确定性规范化，不能仅依赖模型服从提示。 |
| 导入 Markdown / ZIP、粘贴富文本 / Markdown | 在内容进入编辑器 / store 前按统一策略转换；保留格式与非标题内容。 |
| 编辑器输入、改变级别、移动标题 | 在合适的编辑事务中维护规范标题，映射光标与选区，进入同一撤销步骤；输入法组合中不处理，不能每次按键删前缀。手写前缀完成后再归一。 |
| 普通创建 / 保存 | 前端提交的内容已是规范内容；后端共用写入边界校验策略版本和规范内容。异常输入明确返回可处理的错误，不能在成功回包里悄悄换成另一份正文。 |
| AI 应用修改 | 在生成 / 修订预览时完成规范化，用户看到的预览与最终应用内容一致；应用时保留原哈希并发校验，不扩大到其他章节。 |
| 历史恢复 | 历史版本原件不改；恢复副本在进入当前文档前升级，再进入共同写入和索引流程。 |
| 复制、导出 | 消费规范结构的显示编号；复制部分标题不擅自加入完整编号；JSON 备份保留内容及策略版本。 |

共享写入边界应由普通笔记、草稿保存、修改应用、恢复共同调用，收敛版本留存、冲突校验、内容哈希与索引失效处理。不能只给 `/notes` 的普通保存增加规则而漏掉草稿 / 预览路径。

## 旧笔记的整体升级

为笔记增加内容策略版本，旧笔记为 legacy，规范笔记为版本 1。版本表示数据格式，不是用户可切换的编号偏好。

1. 先提供只读扫描报告：待升级数量、确定可转换数量、歧义数量、预计变更。每篇校验非标题内容与格式没有变化。不限于 Docker 和 Redis，不把“全量升级”等价于挨篇模拟点击按钮。
2. 使用可重试的升级任务处理当前授权范围。每篇按主键 / 内容哈希校验并加锁，在同一事务中保留原版本、写入规范内容、更新策略版本和哈希、标记索引待更新。
3. 本地未同步编辑、离线日志、活动编辑器和待确认 AI 修改的笔记暂缓，待安全边界再处理。不能用升级覆盖当前输入，也不能让服务器批处理绕开客户端的未保存状态。
4. 任务中断可以续跑；版本 1 的笔记重复扫描不再改写、不新增历史、不触发重复索引。歧义项保持原件并在报告里说明，不能默认为成功。
5. 在工作区升级阶段协调客户端缓存与服务器版本。GET 仍然只读，不能让每次打开笔记都顺便写库或触发保存。当前编辑器只有在确认无新输入的受控切换点才能采用升级结果。
6. 升级完成后，正常使用不出现「统一编号」维护按钮。维护工具只保留诊断 / 回滚用途。回滚依据实际留存的历史与策略版本，不靠内存中的上一次编辑器对象。

本轮只做方案与只读扫描，未运行数据库批处理。实施时先完成干跑报告、冲突 / 回滚验证，再按已确认的账号范围执行；其他账号与已删除笔记不进入默认目标。

## 验收

- 同一份混合序号笔记分别通过生成、导入、粘贴、编辑保存、AI 应用和恢复进入系统，规范标题及显示编号一致。
- 所有编号结果与笔记名称 / 指定两个样例无关；随机章节名、重复标题、章节重排和真实层级变化都正确。
- 文档主标题不编号；普通一级 / 二级章节计数正确，旧序号不驱动规范计数器。
- 代码、正文、有意义的数字、标记格式、换行和引用不被错误清理；歧义不静默处理。
- 真实编辑中不跳光标、不丢选区，输入法不提前提交，撤销 / 重做覆盖同一编辑动作。
- 保存成功不因格式转换调用 setContent；迟到回包、离线编辑、409 冲突和已打开 AI 预览都有明确保护。
- 升级完整 / 中断恢复 / 重复执行 / 回滚均在隔离数据库验证，检查历史与索引行为。
- 通过旧笔记全量只读报告和代表性真实端到端验证后，才声明底层统一完成。
