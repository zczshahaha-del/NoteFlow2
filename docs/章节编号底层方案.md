# 标题编号：采用与标题一体的可编辑文字

2026-10-22 纠偏。用户明确指出编号编辑手感不对，并要求按照其 Notion 页面执行。本方案替代 `fbb48a7` 的显示层自动编号设计，保留该提交的字体、阅读列、标题排版与目录交互。

当前状态：`8dbb791` 只完成去除显示层与恢复普通文字编辑，随后被用户指出“标题序号都没了”，不是完整交付。生成端仍清除标题编号，缺少将结构编号写入实际内容的衔接；以下现行实现及测试仅证明局部编辑行为，不能证明用户的完整目标已实现。

## 生成与编辑的闭环（待实施）

- 文稿形成时：在生成结果组装成正式稿的边界，统一按实际标题结构生成 `1.` / `1.1`，写入真实标题文字；草稿预览、保存与正式编辑看到同一份文本。文档主标题不编号，代码 / 普通正文不改。不是只换提示词，也不是前端再盖一层数字。
- 普通编辑时：数字已是内容，允许逐字改删；不会在输入、保存或重开时自动补回。目录、复制与导出只读取真实内容，不维护第二套序号。
- 本次失号恢复：先核对受影响文档和旧版本，生成只涉及标题的确定差异，保证可恢复后再一次性落地；不盲目给所有无号笔记补号，不反复在打开时迁移。
- 验收：必须覆盖“新生成文稿有真实编号 → 编辑器能删改 → 保存重开仍一致”和“受影响旧稿恢复”，而非只验证无号不补。当前这些目标尚未实现或运行验收。

## 参考证据与产品选择

只读检查用户指定的 Notion GORM 页面：`4.1 增（Create）` 与 `4.3 改（Update）` 各自位于同一个 `contenteditable=true` 标题元素中的文本节点，`::before` / `::after` 均为 none。数字属于标题内容，不是外挂的自动编号。这里只能证明这页的实际呈现，不推断 Notion 所有块类型或内部后端。

NoteFlow 采用相同的编辑语义：

- `4.1` 是普通标题文字，可放置光标、逐字删除、选中、修改与复制。
- 删除序号不自动生成回来。回车使用普通标题编辑行为，不复制或自动续编号；空标题仍不进目录。
- 未写编号的标题不凭空补号。重排标题不偷偷重写其数字；不引入新的列表续号或章节编号开关。
- 层级只由 H1–H6 决定，不凭 `一、`、`4.1` 猜层级。正文和目录读取同一份真实标题文字，不产生第二套编号。

## 8dbb791 的现行实现（缺少生成端衔接）

1. 使用 Tiptap 标准 Heading，移除 `StructuredHeading` 的 sourcePrefix 属性、编辑后自动转换及组合结束重写逻辑；不存在隐藏的编号字符或不可编辑编号节点。
2. `outlineHeadings` 只派生目录缩进，保留文字。`DocumentTitleDisplay` 只标识与文件名相符的首块 H1 来控制主标题排版，没有编号 Decoration 或剪贴板重写。
3. 桌面 / 手机目录均显示原始标题；阅读 / 光标追踪继续排除重复文档主标题。只为匹配旧服务端章节记录时使用保守序号忽略，不改编辑器文字。
4. 标准剪贴板带标题中实际存在的文字；部分选中数字即只复制选中的数字。Markdown ZIP / JSON 都导出原始源内容，不重新编号、不清理特殊 Markdown。
5. 保留标题 / 对照显示事务不触发保存的既有保护，保留内容缓存、原生撤销和 AI 预览源哈希契约。

不批量写库、不迁移笔记、不根据之前的显示编号反推并补写源内容。历史上已显式清理的标题不会被擅自恢复或补号；需要编号时用户可直接写入标题。AI 草稿原有无手写序号生成规则本轮不扩大修改范围，不宣称新增了自动文字编号功能。

## 验证

真实 Tiptap 单测覆盖 H1–H6 原文及粗体保留、零加载保存、逐字删号、删除后重开、HTML 粘贴、拆分、撤销 / 重做；目录层级包含 40 组、每组 25 个不同级别 / 前缀标题，输出文字与输入一致。剪贴板、部分数字复制、粘贴及 ZIP / JSON 原文导出覆盖 CRLF、嵌套、Setext 和特殊 HTML。
