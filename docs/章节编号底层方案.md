# 标题编号：生成时写入，编辑时保留

2026-10-22。替代 `fbb48a7` 的显示层自动编号方案，并补齐 `8dbb791` 只恢复编辑语义、未衔接生成端而造成的失号问题。保留既有 Notion 参考排版、阅读列和目录交互。

## 产品规则

AI 决定内容与标题结构；NoteFlow 在新文稿形成时按结构写入一次真实编号。编辑器接收的已经是 `## 1. 基础`、`### 1.1 定义`，不是标题外盖一层数字。

- 默认所有新稿统一使用 `1.` / `1.1` / `1.1.1`，文档主标题不编号。
- 逐章生成按该章节在有效大纲中的全局位置编号；第三章从 `3.`、`3.1` 开始，已删除章节不占号。
- 层级只由 H1–H6 决定，不根据编号文字猜层级。模型误把章标题写成 H1 时，在生成边界按指定章节级别平移相对层级；不改代码中的 `#`。
- 用户明确要求“一级标题使用中文编号”时，章级使用 `一、`、`二、`，子级仍使用十进制路径。正文补充中明确的编号要求优先；不因正文里出现中文数字就随机切换风格。这是有限的显式表达识别，不宣称理解所有自然语言编号要求。
- 进入普通编辑后，数字就是文字：允许逐字删除、修改、选择与复制；保存、重开、普通 AI 局部修改不补号、不重排。
- 显式重新生成大纲、工作台章节重排或整稿组装才重新按结构编号；不是每次普通保存触发。工作台重排前保留章节版本。
- 目录、复制、Markdown ZIP、JSON 都读取同一份实际文字，不维护第二套计数。

## 实现边界

`server/app/services/heading_numbers.py` 使用 MarkdownIt 的块解析与源位置，在生成边界统一前缀；保留非标题字节、代码、列表、CRLF 与行内格式。支持常见中文、阿拉伯旧前缀，保留 `2026 年总结`、`3D`、`1.5版本` 等没有明确序号分隔符的名称。多行 Setext 或无法安全映射的跨标记前缀拒绝处理，不猜测并改写原文。年份后带点等语义歧义无法仅凭文本百分百区分，不能声称任意格式无损归一。

| 文稿阶段 | 写入编号的位置 |
| --- | --- |
| 新建 / 重新规划大纲 | 大纲与章节 provenance 文本；内部标题元数据保持纯名称 |
| 前台逐章生成 | 仅 `source=generate_section` 时按全局章节路径写入 |
| 后台全部生成 | Worker 落库前统一；异常标失败，保留原正文 |
| 完整组装 / 未组装草稿首次形成笔记 | 完整结构统一一次；避免未生成章节重复插入同一个标题 |
| 已组装草稿保存为笔记 | 原样使用已组装文本，不复活手动删除的编号 |
| 普通保存、编辑、复制与导出 | 不调用编号归一；无加载迁移或不可编辑编号节点 |

提示词让模型专注结构，不自行算号；确定性处理负责最终编号，不能只依赖模型“听话”。前端章节名称清理同步改为保守前缀识别，避免把 `2026`、`1.5版本` 当编号删掉。

编辑器使用标准 Tiptap Heading；`DocumentTitleDisplay` 只识别重复文档主标题排版，不生成编号。只有服务端旧章节定位比较忽略已知前缀，不改用户正文。

## 本次旧稿恢复

只处理此前明确清理过编号的 Docker、Redis 两篇，不给其他旧笔记硬加号，也不在打开任意笔记时迁移。

`scripts/repair-heading-numbers.py` 为显式运维入口：仅本地 development 库、精确账户与笔记 ID；默认 dry run，应用要求核对过的源 / 目标 SHA-256。全部候选先校验再写；待确认 AI 预览、其他账户、哈希变化或非编号差异均拒绝。事务内先保存完整 NoteVersion，再更新内容与排队正常索引；脚本不提交用户内容、数据库或私密 ID。
