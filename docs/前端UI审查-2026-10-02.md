# NoteFlow 前端 UI 审查与优化顺序

日期：2026-10-02；源码基线：`a816174`。

## 结论与边界

最主要的问题是局部精修后的组件与旧组件混在一起：账号、目录行、聊天正文已经改善，但各类菜单、草稿、修改预览仍使用另一套表面、按钮和文字规则。下一步应统一现有功能的状态与视觉语言，不再凭空补功能或重新安排整页。

本轮为源码 / CSS 审查，结合此前用户反馈，不是新一轮浏览器逐页视觉验收。此前本地自动浏览器访问被策略拒绝，本轮不改用其他通道绕过。下列尺寸是代码值或公式推导，不能作为当前真实像素、越界、帧率或读屏证据。用户当前浏览器状态、账号、笔记及偏好没有操作；仅增加审查文档和问题记录。

## 已经改善、应保留的部分

- 目录使用整行反馈、文件夹 / 选中项字重层级，原排序和业务回调不变。
- 圆润无箭头侧栏切换图标及其他已批准的精修图标，不再退回旧候选。
- 单一头像 + 真实用户名入口、整行悬停与菜单对齐；账号名称已移除原生 title。
- 统一设置容器及 OverlayDialog 已有焦点管理、进退过渡；不是仍然完全散落的旧设置方案。
- AI 正文已去掉回复外框；“正在思考”只在无正文时显示，正文到达即隐藏。不要再重复修复这个已改分支。
- 正文已有桌面稳定几何：两侧先占空白，触及内容边界后才移动 / 缩窄正文。全局已有 reduced-motion 回退，不是完全没有动效或无障碍支持。

## 跨区域的规则

1. 表面不要每层都加线：正文保持安静；菜单用柔和浮层；真正的输入和危险确认保留必要边界。不能简单删除所有边框。
2. 建立有层级的字号、字重、行高与间距。优先解决 `font: inherit` 与 Tailwind 分层冲突，不对全页面盲目增字号；数字值需通过计算样式复核。
3. 图标继续沿用现有库，分别校准形状、视觉中心与重量。视觉统一不等于所有图标都用完全相同的尺寸 / 笔画；保留已批准的圆润切换符号。
4. 动效用于解释状态：按钮即时反馈、菜单短距离淡入 / 退出、抽屉开合、正文与面板协调。当前面板宽度 300ms、正文宽度 / 位移 160ms，建议协调节奏；是否有卡顿须实测，不能从 duration 不同直接定性。140 / 180 / 220ms 可作候选档位，不是 Apple 官方参数。
5. 默认 / hover / pressed / keyboard-focus / selected / disabled / loading / error 要成套评审。当前不是所有状态都缺失，避免把已完成组件重复推倒。
6. 浅色、深色、减少动效与高对比一起验收；硬编码浅色 hover 仍需按消费者核查，不能仅凭 `.theme-dark .bg-white` 的全局补丁判断完成。

参考方向：[Apple 布局指南](https://developer.apple.com/design/human-interface-guidelines/layout)强调视觉层级；[Apple 动效指南](https://developer.apple.com/design/human-interface-guidelines/motion)把动效用于状态、反馈和引导。这里借鉴原则，不声称使用 Apple 组件或一比一复刻 Codex。[W3C Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible)要求键盘用户能识别当前焦点，不能为了去框而删除所有键盘反馈。

## 本轮新确认的状态缺口

AI 会话历史的重命名 / 删除按钮存在于 DOM 中，但仅 `opacity-0 group-hover:opacity-100`，未像目录更多按钮那样补 `group-focus-within:opacity-100`。键盘焦点进入行内按钮时没有对应的可见性规则，触屏无 hover 的发现性也待验收。源码位置：AIPanel.tsx 约 1047–1059；对照 DirectoryTree.tsx 约 355–359。

记录为 UI-23：未解决。本轮不实现；后续优先补焦点显现并验证 Tab / Shift+Tab / Enter，触屏入口策略单独确认。现有组件测试通过不证明这个没有覆盖的状态已通过，也不声称已在实体设备复现。

## 不可把“有代码”当作“当前可见”

主编辑器的完整格式工具栏仍在 `false &&` 分支；AttachmentPanel、NoteRelationsPanel、NoteMetadataControls 没有在正式编辑器挂载，元数据组件的测试导出不等于产品入口。版本历史也需要核对实际触发入口，不能只因存在组件就画成常驻栏。本轮不恢复这些功能，不设计不存在的仪表盘、最近阅读、协作成员或统计卡片。

## 建议实施顺序与验收

先以所有实际菜单做一张连贯状态对照，统一视觉语言；再分别处理搜索、草稿、修改预览；然后检查正文 / AI 比例和窄屏。每个模块先确认局部图，保留原回调，独立提交和备注。

每轮验收至少包含：真实长短文本、键盘操作、加载 / 失败、浅深色、窄屏；涉及生成的模块再补首字等待、输出、停止、重试及完成状态。涉及数据动作的 E2E 使用专门合成数据，不能为了截图操作真实笔记。

本轮验证：`npm run test:frontend` 和 `npm run test:editor-ui` 通过；`check:dev-ports` 通过，原服务保留。DEV-11 的 Node 弃用警告仍存在。没有正式代码修改，没有新增运行截图、浏览器几何、帧率、深色视觉或真实写入 E2E 证据；设计建议均待评审。
