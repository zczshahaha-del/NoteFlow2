# 工作台连续操作：跨区域订阅与回归

## 范围与证据口径

本轮对应六项优化的第 6 项，沿用 UI-27 的重复计算问题。实际 App / NoteEditor / DirectoryTree / AIPanel / Zustand store 与构建 CSS；认证、初始化和 HTTP 使用合成替身。不是生产模型、真实账号或用户笔记的端到端测试。

测试连续执行：从知识库切篇 → 滚动 → 在可见段落选择文字 → 点击高亮 / 撤销 → 输入 → 打开 / 收起 AI → 流式呈现 → 调整窗口 → 返回已编辑笔记。没有在每一步重新挂载整个测试页面。配置为 1277 / 800 / 320px；触屏仅浏览器配置，选区用编辑器 API 建立、格式按钮用原生点击，不能称为实体触屏选字验收。

合成负载：两篇各 80 标题 / 20 个 Go 代码块的长笔记、120 篇目录、40 条含代码的历史聊天；输入 10 个字符，另有 20 段合成流状态更新。计数探针只注入离线 bundle，不进入正式应用。

## 根因与处理

- App 只需要选中文字引用，却订阅全部聊天消息，流式增量会重画整个工作台。
- AI 面板、知识库和文件行订阅宽泛的编辑 / 工作区 slice。正文缓存、保存状态和活动章节变化会唤醒无关界面。
- 仅删去正文缓存订阅不够：每次输入还会更新完整树的 content / indexStatus，treeData 引用随之改变。首次缩小订阅后，输入阶段仍实际产生 10 次聊天与知识库重画，预算断言失败；没有把此中间版本当完成。

处理仅限订阅与导航元信息视图：App 精确订阅 chatSelection；AI 和目录使用局部 slice；导航视图按 ID、名称、结构、日期、标签、收藏 / 置顶等字段保留稳定引用，忽略不在导航展示的正文、正文哈希和索引状态。投影弱缓存，不复制 / 缓存彩色 HTML，不改原 store 的完整正文、树结构写入或保存逻辑。导出在点击时读取最新 fileContents，缺少缓存时从原始树读取正文，避免导出旧闭包内容。

更名、移动、删除、日期、收藏 / 置顶仍刷新导航；正文每次输入依旧立即更新 store / 原本的本地日志与保存调度，没有为了性能少存内容、推迟输入或丢失撤销。

## 旧提交与本轮对照

旧提交为 `c7ef21b`。在同一套夹具中装载该提交的 App、AI、目录和 selector 入口源码；CSS 没有本轮变化。正常回归以工作区源码执行硬性工作量断言。

1277px 结果（次数，不是耗时）：

| 阶段 / 指标 | 旧提交 | 本轮 |
| --- | ---: | ---: |
| 输入 10 字符：AI 面板渲染 | 10 | 0 |
| 输入 10 字符：知识库渲染 | 10 | 0 |
| 输入 10 字符：全部文件行累计渲染 | 1210 | 0 |
| 输入 10 字符：正文序列化 | 10 | 10 |
| 流更新：App 渲染 | 21 | 0 |
| 流更新：正文渲染 | 22 | 0 |
| 流更新：文件行累计渲染 | 2541 | 0 |
| 输入 / 流更新：未变代码解析 | 0 | 0 |
| 输入 / 流更新：历史 Markdown 重解析 | 0 | 0 |

800px 输入旁支计数同上；320px 原知识库已卸载，因此输入时目录本来就是 0，不虚报手机目录收益。三宽度 AI 输入旁支渲染均 10 → 0，流更新 App 均 21 → 0、正文 21～22 → 0。聊天本身仍按新增正文正常呈现，不要求它停止渲染。

旧版与本轮主要阶段均未采到超过 50ms 的 longtask；切篇阶段最大帧间隔约 17～33ms，输入 / 阅读 / 流更新约 17ms。探针覆盖有限、机器性能和驱动交互影响采样，本轮没有复现用户所有严重卡顿，不据此声称固定 60fps 或已找出唯一性能根因。确定的成果是消除无关 React 工作，非网络延迟或模型首字性能提升。

## 自动验证与复跑

```sh
npm run build
npm run test:navigation-tree
npm run test:workspace-flow
NOTEFLOW_FLOW_BASE_REF=c7ef21b npm run test:workspace-flow
```

浏览器脚本需要现有 Playwright 和浏览器路径配置，沿用其他 UI 回归的 `NOTEFLOW_PLAYWRIGHT_MODULE` / `NOTEFLOW_BROWSER_EXECUTABLE`，不额外下载运行时。结果和合成截图保存在系统临时目录，仓库不提交浏览器数据。

新检查覆盖完整链中高亮 / 撤销、编辑器与文档身份、未发送 AI 草稿 / [2,6] 选区 / 窗口改变时焦点、重开笔记的输入、颜色、无横向溢出、没有 pageerror 或外部请求。导航投影单测覆盖正文 / 索引变动稳定、快照重用、6 种元信息变更、删除、移动和不修改原数据。正式目录组件补“菜单已开、正文变更后再导出”，验证读取最新未同步正文；不是系统下载。

夹具纠偏：初稿错误查找显示中已去掉的 `.md` 后缀、把没有 textbox 角色的正文当 textbox、选中了滚动区外首段、手机误点章节目录而非知识库入口；按正式名称、真实 contenteditable、可见段落和「打开知识库」修正。人工核对截图又发现合成 Response 漏 JSON Content-Type，曾留下保存错误提示；补齐契约，增加等待真实 store saved / 无 alert 硬断言后完整重跑旧提交与本轮三宽度，最终均通过，截图无错误提示。未改产品角色、入口、正文或断言预算来迁就夹具。

关联聊天回归一次在固定 150ms 等待后采到 opacity=0.999592，而不是最终 1；改为等待浏览器实际最终值，再保留原精确显隐 / 同组时间断言，不关闭动画、不放宽成容差。最终 chat-ui 和真实 SSE reader 合成 30 段 / 0、10、30 历史的诊断通过，历史解析仍为 0。

最终回归：build、frontend（46 组组件 / 10 项 store）、editor-ui、navigation-tree、input-composition（6）、local-note-journal（17 字符对应 17 次局部日志写入）、note-save-scheduler（5）通过；library-navigation、workspace-layout-ui、note-entry、editor-performance、outline-reading-ui、chat-ui、library-motion、selection-toolbar-ui 均通过相应多宽度。源码未修改编辑器内容 / 动画 CSS，原章节跟随、高亮撤销、复制 / 中国时间、保存上传重试、目录结构动作和宽度 / 焦点行为保留。

长文伸缩关联回归曾在并行测试时采到 218ms 帧间隔，不能用 longtask=0 否认该间隔。后续顺序执行本组时为 37 / 38 / 54 / 54ms，1700px 阅读位置、同一编辑器 / 文档、单按钮连续移动和 7200 个代码 token 均保留。没有证据证明首次间隔的唯一成因；本轮不修改产品动画、不承诺全程 60fps，实机帧时仍待验证。
