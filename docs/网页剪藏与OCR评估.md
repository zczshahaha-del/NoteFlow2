# NoteFlow 网页剪藏与 OCR 评估

评估日期：2026-07-15

## 结论

网页剪藏和 OCR 暂不进入当前核心版本。优先保证编辑、搜索、AI 草稿、安全修改、记忆、离线同步的可靠性。

网页剪藏后续采用“两级方案”：移动端优先使用 Web Share Target 接收链接和选中文本；桌面端在验证需求后提供轻量浏览器扩展。剪藏内容必须保留来源 URL、标题、作者、抓取时间和正文快照，并默认进入收件箱，不直接污染正式知识库。

OCR 采用可替换适配器，不与附件上传耦合。图片/PDF 上传先正常保存，用户显式触发识别后再生成可审阅文本；原图、识别文本、语言、页码和模型版本分别存储。低置信度结果不得自动进入 RAG 索引。

## 进入实现阶段的条件

- 附件处理队列具备独立资源限制、重试和失败状态；
- 明确网页正文清洗规则、版权提示和隐私边界；
- OCR 有至少两种可替换实现及成本上限；
- 剪藏和 OCR 文本均有用户确认、来源追踪与重新索引入口。

本次只完成产品与技术评估；延后实现是明确范围决策，不作为当前版本阻塞项。
