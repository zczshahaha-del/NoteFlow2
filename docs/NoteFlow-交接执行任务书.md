# NoteFlow 交接执行任务书（唯一执行依据）

> 目的：把 NoteFlow 收敛成一款**阅读优先、由 AI 生成课程并供用户学习与修改的个人笔记软件**。本文件给下一个执行 AI 直接使用；实施时以本文件为准，不要再自行扩展成“工作台”“仪表盘”或堆砌功能。

## 0. 先读这一页：产品已经做出的决定

### 0.1 产品一句话

用户几乎不手写笔记：他和 AI 简单确认学习目标后，AI 生成一整篇可继续阅读、可修改、可检索的学习笔记。用户在笔记中学习、选中不懂的内容提问、补充自己的理解。

首位用户的典型目标：从零学习并能应对“大模型应用开发工程师”相关面试，重点包括 RAG、工具调用、记忆、LangChain/LlamaIndex、Agent、Trace/可观测性、评估和工程化。

### 0.2 绝对优先级

1. **阅读正文的质感第一。** 功能再多，正文不好看、不想读，就算失败。
2. **简单。** 左目录、中正文、右 AI；不要“工作台”、数据卡片、任务中心、复杂设置常驻在主界面。
3. **AI 是课程作者，用户是学习者和验收者。** 生成不是聊天长文的附属功能，而是产品主流程。
4. **用户选择范围，系统不猜范围。** 对话与全库检索是明确模式，不要把“是否使用知识库”藏在不可解释的意图判断里。
5. **保留真实数据和已有能力。** 不因改 UI 删除账号、笔记、RAG、记忆、草稿、索引或登录能力。

### 0.3 必须保留，不能误删

- 用户账号、密码、已有笔记、分类/文件夹、笔记版本、附件。
- HttpOnly Cookie 会话登录、服务端可撤销会话、JWT 短期访问令牌机制。
- 原有 `localStorage` Bearer token 的**一次性迁移**兼容逻辑；迁移完成后必须删除旧 token，普通请求绝不能同时带 Cookie 和 `Authorization`。
- AI 意图/上下文规划、生成笔记草稿、分节后台生成、断点/失败重试、保存为正式笔记。
- 笔记索引、向量检索、关键词检索、DashScope embedding、记忆系统、引用跳转。
- 编辑、版本、离线队列/冲突处理等已有基础能力。

### 0.4 本轮明确不要做的事

- 不要把 Markdown 源码编辑器或“查看 Markdown”作为普通用户入口；用户要像编辑普通文档一样编辑。
- 不要重新设计登录体系为 localStorage token；当前 Cookie 方案保留。
- 不要把 RAG 当作所有普通聊天的默认强制步骤。
- 不要用一大堆死规则硬编码每个主题的大纲和每句话的回答。
- 不要新增独立“AI 工作台”“生成中心”“知识库管理大屏”。
- 不要因 UI 改造删除数据库、清空 localStorage、重置用户数据，或在未经确认时修改生产数据。

## 1. 当前工程事实与风险

### 1.1 技术栈与入口

- 前端：React + Vite + TypeScript + Tiptap。
- 后端：FastAPI + SQLAlchemy + PostgreSQL + pgvector + Redis（可选）。
- AI：DeepSeek；向量：阿里云百炼 DashScope `text-embedding-v4`。
- 本地启动：`npm run dev`，前端默认 `http://127.0.0.1:5173`，后端默认 `http://127.0.0.1:8080`。
- 前端构建与现有检查：`npm run build`、`npm run test:frontend`、`npm run test:e2e-runtime`。

### 1.2 当前已有但需要收敛的实现

| 能力 | 当前位置（供执行 AI 定位） | 处理原则 |
|---|---|---|
| 主界面/样式 | `src/App.tsx`、`src/index.css` | 重构为三栏阅读界面，不能只隐藏工作台标题就算完成。 |
| 正文编辑 | `src/components/NoteEditor.tsx`、`src/components/TiptapPilotEditor.tsx` | 保留编辑能力，重做视觉和代码块交互。 |
| 右侧聊天 | `src/components/AIPanel.tsx` | 收敛为干净的 AI 对话面板，删掉常驻的任务/运行细节卡片。 |
| AI 草稿生成 | `src/components/AIDraftWorkspace.tsx`、`src/services/drafts.ts` | 不再作为独立工作台式页面；改成课程生成流程并保存回目录。 |
| 大纲/正文提示词 | `server/app/services/prompts.py` | 保持“格式契约 + 用户完整需求”，避免主题硬编码与规则膨胀。 |
| 意图和上下文 | `server/app/services/context_planner.py`、`server/app/services/agent_runtime.py` | 只用于生成笔记、编辑等动作；不用于偷偷猜是否 RAG。 |
| RAG | `server/app/services/embedding_index.py`、`markdown_index.py`、`pgvector.py`、`note_library.py` | 只在“全库搜索”模式主动运行；修复重复、标题不一致、跳转不准。 |
| 登录 | `server/app/routers/auth.py`、`src/services/auth.ts`、`src/services/api.ts` | Cookie 为唯一正常请求身份来源；彻底审计旧 token 迁移。 |

### 1.3 已暴露的真实问题（必须逐项验证）

1. 代码块工具栏出现闪烁、悬停失效、语言下拉没有列表、复制按钮文字被遮挡，甚至整块像图片无法点击。
2. 代码块视觉不像参考图：字体/颜色/背景/边界层级不对，工具栏像原生控件。
3. 正文、生成笔记页、聊天渲染页的字体、字号、行距、代码块没有统一。
4. 右侧 AI 面板仍混入“当前任务/近期任务/自动识别”等系统感很强的内容。
5. RAG 曾出现：同一段多次命中、标题不一致、引用不能跳到准确小节、引用下方展开一大段 Markdown 原文。
6. 生成大纲曾偏离用户真实需求，生成成机器学习训练课程；大纲层级过深、每一项又带小纲领。
7. 生成 API 曾返回 `too many AI requests, please try again later`，必须让用户看到可理解、可重试的状态，而不是无意义红字。
8. 用户曾登录后看到空笔记。必须对 Cookie 与 legacy token 的身份优先级和迁移路径做回归测试。

## 2. 目标信息架构与页面规范

### 2.1 唯一主界面：三栏，不要工作台

```text
┌────────────── 左侧目录 ──────────────┬────────────── 中间笔记正文 ──────────────┬──────── 右侧 AI ────────┐
│ + 添加知识                            │ 笔记标题                                  │ AI 助手                 │
│ 目录                    ↻  多选  搜索  │ 创建于 2026-.. · 更新于 2026-..            │ 当前笔记标签（可移除）   │
│ ▾ 大模型应用开发                       │                                            │ 选中文段引用（可移除）   │
│   ▾ RAG                                │ 正文：教程式阅读体验                       │ 对话 / 全库搜索 ▾        │
│     • 检索、召回与重排                  │ - 标题、段落、代码、提示卡                 │ 多轮消息                 │
│   • Agent 与工具调用                    │ - 默认阅读，点击正文直接编辑               │ 大输入框                 │
│                                         │ - 边缘“本文目录”按钮，按需展开             │                          │
└────────────────────────────────────────┴────────────────────────────────────────┴──────────────────────────┘
```

### 2.2 左侧：目录

- 顶部只保留 `+ 添加知识`（导入/创建入口）。不展示产品名称、Slogan、冗余统计卡。
- 标题为“目录”，不是“知识库”。
- 右侧仅三个图标按钮：刷新、多选、搜索笔记；每个有 tooltip 与可访问名称。
- 目录呈现真实文件夹/文件树。支持展开、折叠、新建文件夹、新建笔记、重命名、移动、删除/回收站、多选操作。
- 搜索笔记是**找文件/笔记标题和正文**，不是 RAG 对话。搜索入口可在目录头部，弹窗/抽屉中提供关键词、结果和定位。
- 选中笔记后正文加载；刷新不会切换账号或清空当前选择。

### 2.3 中间：笔记正文（产品第一优先级）

#### 视觉基调

- 以 `noteflow-layout-preview.html` 的正文区域为唯一视觉参考。先仔细阅读该 HTML/CSS，再迁移 token 和布局；**不要凭印象重画另一套**。
- 白色阅读面，留白足，正文内容区宽度舒适（建议 720–840px），不要铺满屏幕。
- 字体优先系统中文无衬线：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`；代码使用清晰等宽字体。
- 视觉层级靠字号、字重、间距完成；不要到处套卡片、边框和蓝色描边。
- 交互控件默认安静，仅 hover/focus 时出现。**不能出现点击正文或聊天输入框就冒出丑陋方框**；保留键盘可见的细腻 focus-visible 样式，不可以粗暴 `outline: none` 后完全无可访问性。

#### 文档头

- 顶部是**真实大标题**，不是淡分类名：建议 32–36px、700 字重（窄屏随比例下降）。
- 标题下只显示：`创建于 YYYY-MM-DD · 更新于 YYYY-MM-DD`。没有分类面包屑、Slogan、无意义摘要、状态胶囊。
- 标题应来自笔记真实 `title`，不得由内容的第一个 H1 重复渲染。若 Markdown 正文也含同名 H1，渲染时只显示一次，编辑/保存时保持数据不损坏。

#### 正文排版

- 以技术学习笔记为主：连续阅读舒服，H2/H3 清楚，正文 16–17px 左右、行高 1.8 左右；标题间距明显但不能巨大。
- 列表、引用、表格、分割线、图片、行内代码均应有一致样式。
- 代码前后有足够但不夸张的间距；浅灰/暖白代码背景要与白色正文可辨，不要融成一片。
- 文档右边缘增加轻量“本文目录”能力：默认只显示一个低干扰小按钮/细标记，点击或靠近后展开章节导航；点击后平滑定位小节，用完可收起。
- 默认阅读模式。点击正文直接进入编辑，不打开 Markdown 源码视图。

### 2.4 代码块：必须按下面做，不接受假交互

#### 外观

- 浅灰暖白背景、圆角约 14–16px、内边距舒适，代码与背景有明确对比。
- 代码使用真实语法高亮：关键词蓝色、字符串绿色、函数/关键字/内置值等有稳定配色；不能只是普通黑字。
- 颜色和字重以 `noteflow-layout-preview.html` 及用户提供的参考图为准：不要过黑、过饱和、过粗。
- 长代码横向滚动，滚动条低调可见；不要强制把长行挤换行。

#### 工具栏

- 位于代码块**右上角、距上边和右边 6–8px**，靠近代码内容。代码块很短时也不能悬在空白很远处。
- 未 hover 时整个工具栏隐藏；鼠标进入代码块或键盘聚焦工具栏后出现；鼠标从代码块移到工具栏期间不能闪烁。
- 一个自定义分段胶囊：`语言名称 + 下箭头 | 复制图标 | 更多`。不使用浏览器原生 `<select>` 外观。
- 复制图标 hover 显示黑色 tooltip `拷贝`，文字必须完整、不被裁切，tooltip 与控件不能重叠。
- 点击复制后复制纯代码；tooltip/状态短暂改为 `已拷贝`，不会选中正文或导致编辑器失焦异常。
- 点击语言名称后打开浮层。浮层包含小搜索输入框，列表至少有 Plain text、Bash、Go、Python、Java、JavaScript、TypeScript、JSON、SQL、HTML、CSS、Markdown；点击选项后更新本代码块语言和语法高亮，浮层关闭。
- 浮层层级必须高于代码块、正文和右侧面板，不可被 `overflow: hidden` 裁掉。

#### 实现约束（为彻底解决当前“死的代码块”问题）

- **不要继续在多处叠加 CSS 覆盖和 `document` 级原生 mousedown 监听。** 现状已有重复 `.code-toolbar` 样式及捕获事件，容易互相覆盖、吞掉点击。
- 将代码工具栏收敛为一个受控组件/一个 Tiptap NodeView（或统一的 React portal），状态只由 `isToolbarVisible`、`isLanguageMenuOpen` 管理。
- hover 状态由“代码块容器 + 工具栏”共同包住，或用 `pointerenter/pointerleave` 与短暂 close delay；禁止在 toolbar 自身 `pointer-events:none` 与子节点 `pointer-events:auto` 间来回切换造成抖动。
- 事件只在该组件处理，语言菜单与复制按钮必须 `preventDefault + stopPropagation`，但不能阻止正文正常选中和编辑。
- 给工具栏、语言菜单、复制行为分别写组件测试/浏览器 E2E；不要只通过 TypeScript 编译就声称修复。

### 2.5 右侧 AI 面板

- 标题简洁：`AI 助手`，辅助文案可为“直接说你想做什么”。不要把 Agent、工具链、RAG、任务状态、运行轨迹常驻暴露给普通用户。
- 对话消息是清晰阅读的气泡/文段，不使用巨大的卡片堆。
- 输入框要大，类似 Notion AI 的轻盈大输入区域；默认不出现厚蓝框。支持多行，Enter 发送、Shift+Enter 换行（输入法组合态不误发）。
- 当前打开笔记默认作为一个可移除的上下文标签，例如 `📄 大模型应用开发学习笔记 ×`；这不是“全库搜索”。
- 用户在正文选中一段后自动追加第二个可移除标签，例如 `引用：…… ×`。AI 明确知道问题针对这段文字。
- 右下/左下有一个简洁模式切换胶囊（不要放在发送按钮旁）：`对话 ▾`，菜单两项：
  - `对话`：只使用聊天历史 + 当前笔记/选中文段（若已附加），**不检索全库**。
  - `全库搜索`：对用户自己的笔记执行检索后回答，展示可点击引用。
- 暂时不显示模型选择器、加号附件按钮；后续有明确需求再加。

## 3. 核心用户流程

### 3.1 主流程：生成一门学习笔记/课程

1. 用户在右侧 AI 面板自然说：“我想学大模型应用开发，目标是能面试，完全零基础。”
2. 系统的模型意图识别将其识别为“创建学习笔记/课程”。它不是关键词硬匹配；若缺少会显著改变课程结构的信息，AI **温和地一次只问一组问题**。
3. 推荐确认问题：基础、目标、学习深度/时间、重点方向。已知信息不得重复问。用户可直接说“按你的建议来”。
4. 确认后，AI 生成**仅一层的课程目录**，先展示给用户。目录中每条只是一句主章节名，约 8–12 条；没有二级小点、解释、代码或正文。
5. 用户可自然语言反馈“加 RAG、Agent、Trace，别讲模型训练”，AI 按完整对话与需求重生成目录。
6. 用户确认目录后，系统自动后台生成全部章节，不要求逐节点生成。进度轻量展示；出现限流/失败时显示“第 N 节暂未生成，可重试”，允许重试失败节，不丢已完成内容。
7. 全部完成后，自动合成为一篇正式笔记，存入用户选定目录并打开该笔记。目录中立刻可见，进入索引队列。
8. 用户可从当前笔记继续阅读、编辑、选中提问、让 AI 续写未完成章节。

### 3.2 生成内容的质量标准

以“大模型应用开发学习笔记”为例，合理的一级目录应覆盖从基础到工程实践的学习路径，而不是机器学习训练课程，也不是十个互相松散的小项目。应能自然涵盖：模型/API 调用、提示词与上下文、RAG、记忆、工具调用、框架、Agent、Trace/可观测性、评估、部署/安全/成本。

但这只是质量校验的例子，**不能把该目录写死**。用户的原始生成需求、此前确认的目标和反馈必须完整传给模型，让模型根据主题自由组织。

### 3.3 正文生成原则

- 生成完整章节，而不是聊天里一大坨散文。
- 每个章节根据内容本身自由安排解释、流程、例子、代码、练习；不要求所有章节机械套“背景/概念/机制/场景/边界/坑”。
- 有代码需求时才提供可读、可运行条件明确的代码，代码与讲解相邻。
- 文风为通俗、耐心、像一份可以从头读到尾的教程，不像企业 PPT 或空泛提纲。
- 不能捏造用户资料、引用、历史记忆或检索到的笔记标题。

### 3.4 后端/提示词实施要求

1. 保留两阶段生成：`outline` → 用户确认 → 后台逐节 `section` 生成 → 自动组装保存。
2. 在 `outline` 请求中，完整注入：原始需求、已确认的基础、目标、重点、偏好、用户对上版目录的反馈。不要只传一个清洗后的主题。
3. 提示词只保留必要的输出格式契约：简体中文、一个标题、一级目录、不含正文/二级目录。内容规划交给模型。
4. 删除或降低会把所有主题导向固定“AI 工程目录”的强制性文本。可以保留很弱的“避免误解：应用开发不是模型训练”的语义提示，但不得成为照抄模板。
5. 模型调用使用当前配置的 DeepSeek Pro（配置项控制，例如 `DEEPSEEK_MODEL=deepseek-v4-pro`；以实际供应商有效模型 ID 为准，禁止在代码里硬写）。请求限流时使用指数退避、有限次数重试和用户可见重试按钮。
6. 生成动作的意图识别可继续使用模型/上下文规划；遇到不确定性不要用硬规则强制跳页。若模型失败，fallback 只做最小兜底，并记录可诊断日志。

## 4. RAG、聊天、引用与记忆：明确边界

### 4.1 不再让系统猜“要不要查知识库”

| 用户选择 | 输入给模型的内容 | 是否检索全库 | 适用场景 |
|---|---|---|---|
| 对话 | 对话历史；当前笔记标签；选中文段标签 | 否 | 解释当前段落、普通聊天、续写/改写当前笔记 |
| 全库搜索 | 对话历史 + 当前问题 + 经检索去重后的笔记证据 | 是 | “我以前笔记里提过什么”“查一下所有笔记里的 Hooks” |

当前笔记和选中文段是用户显式操作或当前页面上下文，不等同于“偷偷跑 RAG”。全库 RAG 只在用户切到 `全库搜索` 后执行。

### 4.2 RAG 检索实现与质量要求

1. 索引单位：笔记 → 标题 → 章节 → chunk；每个 chunk 必须保存稳定的 `note_id`、`section_id`、`heading_path`、`chunk_id`、文本范围/锚点。
2. 检索：关键词/标题匹配 + 向量相似度混合；对相同 `note_id + section_id` 和高度重叠 chunk 做去重/合并。
3. 结果展示：一条引用只显示**笔记标题 + 章节标题 + 极短摘要**。不要在回答下方默认展开一长串 Markdown 片段。
4. 点击引用必须：打开正确笔记 → 等待正文渲染 → 滚到正确章节/文本锚点 → 临时高亮命中内容。失败时可见提示并记录错误。
5. 不得改写真实笔记标题作为引用标题；引用标题必须来自数据库笔记/章节实体。
6. 没有足够证据时回答“在你的笔记中没有找到足够依据”，不能编造引用。
7. 检索回答的系统提示词要求“只基于传入证据陈述事实，无法支持则明确说不知道”，但不要把内部 RAG、chunk、向量等词展示给用户。
8. 增加固定回归集：至少覆盖同词多章节、相邻章节、同段重复 chunk、标题相似但正文不同、中文标题、代码问题（如“列表与字典的浅拷贝与深拷贝是什么”）。指标至少有：正确笔记命中率、正确章节命中率、重复率、可跳转率。

### 4.3 记忆与“我叫什么”

- “我叫什么/我的账号是什么”应读取当前已认证用户资料，再由模型自然回答；不能写死一句“我不知道您的名字”。
- 长期记忆是可选辅助上下文，不应覆盖当前用户身份数据，也不能对用户展示“系统在读取记忆”的内部实现。
- 用户当前请求优先级高于历史记忆。记忆应可查看、删除、关闭。

## 5. 认证与数据完整性任务

### 5.1 最终会话规则

1. 正常登录成功后：后端设置 HttpOnly `noteflow_session` Cookie；前端不保存访问 token 到 localStorage/sessionStorage。
2. 每次正常 API 请求只携带 Cookie（`credentials: include`），不附加 `Authorization`。
3. 旧版 token 仅允许走一次专用迁移端点：迁移端点验证 token → 创建 Cookie 会话 → 客户端立即删除 legacy token → 后续请求不再读取它。
4. 如果 Cookie 已存在，legacy token 绝不能抢占身份；服务端也不得优先解析 `Authorization` 覆盖当前 Cookie。
5. 登录、登出、切换账号、Cookie 过期、迁移失败均必须清晰处理前端缓存与 React Query/Zustand 用户数据，不能显示上一个账号数据，更不能误把当前用户查成空账号。

### 5.2 必做回归测试

- 只用 Cookie 登录账号 A，刷新、重开页面，笔记仍是 A 的。
- 浏览器残留账号 B 的 localStorage legacy token 后登录 A：请求只认 A；A 的笔记列表正确；旧 token 被删除。
- 登出 A → 登录 B：不会看到 A 的笔记；再登录 A 可恢复 A 的笔记。
- Cookie 失效后会回到登录，不会悄悄请求到匿名/空用户。
- 所有上述测试不得通过清空数据库来实现。

## 8. 给执行 AI 的工作纪律

1. 每完成一个 Phase，先运行对应测试和真实页面验证，再继续下一个；不能只改 CSS 就称“UI 已完成”。
2. 如果用户看到的页面“完全没变”，先查：当前前端端口/进程、浏览器是否加载正确 Vite 地址、实际路由使用的是哪个组件、CSS 是否被旧规则覆盖。不要继续盲加样式。
3. 遇到“点击无效”，先用浏览器开发工具/自动化确认事件是否触发、浮层是否被裁切、是否有覆盖层；不要再追加全局 capture 事件碰碰运气。
4. 任何涉及认证、数据库迁移、索引重建的改动，先做只读检查和备份策略；未经明确许可不要删除数据。
5. 任何模型质量问题，先记录“用户完整输入 → 实际组装 prompt（脱敏）→ 模型响应 → 前端解析结果”，分清是 prompt、模型、解析还是 UI 问题；不要靠不断加死规则掩盖。
6. 用户不需要看到“RAG、Agent、工具、trace、chunk”这些内部术语，除非他主动问技术实现。

## 9. 最终验收场景（全部通过才叫完成）

### 场景 A：阅读与代码

打开一篇 Go/Python 学习笔记：标题、日期、正文、提示卡和代码块符合预览 HTML 的统一质感；正文不会太大；代码块 hover 出现工具栏，复制 tooltip 清楚，语言下拉和搜索可用，代码有语法颜色，点击正文仍能直接编辑。

### 场景 B：当前笔记解释

在“RAG 学习笔记”选择一句不懂的话，右侧出现引用标签。用户保持 `对话` 模式问“这句是什么意思？”AI 只根据选中内容和当前笔记回答，不跑全库；没有“自动/当前笔记/支持库”等生硬分类。

### 场景 C：全库检索

用户切换 `全库搜索`，问“我之前写过的列表与字典的浅拷贝与深拷贝是什么？”回答展示少量不重复来源；每个来源标题和章节真实；点击后跳到对应笔记与文字。

### 场景 D：生成课程

用户输入完整目标后，AI 先温和确认缺失信息，再生成仅一级目录。用户确认后不必逐节操作，自动得到并保存一篇完整“大模型应用开发学习笔记”；内容路线正确，不是模型训练大纲。

### 场景 E：重新登录

账号登录、刷新、重启前端、再次登录后，仍只看到自己的原有笔记；没有因为旧 token/Cookie 产生空账号或错账号。
