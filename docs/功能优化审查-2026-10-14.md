# NoteFlow 功能优化审查 · 2026-10-14

> 正文保留修复前审查证据；用户批准后的四项修复和最新验证见文末「顺序修复」。不把功能增强候选混入本轮漏洞修复。

范围：用户要求检查功能优化空间；本轮审查，不修改 `src/`、后端、UI、配置或用户数据。先查既有问题记录，再核对真实入口与 store / API 调用链；新增隔离诊断脚本，不发邮件、不调用模型、不创建真实笔记。

## 优先级结论

先补编辑 / 保存 / 恢复的可靠性，再补阅读导航和快捷操作。不能因单篇打开保护、本地日志、聊天显示测试通过，推断所有异步回写和服务端同步已经安全。

### 第一轮：正文与保存可靠性（最高优先）

1. **新建和整库刷新不能覆盖输入（沿用 UI-30）。** `src/store/index.tsx` 的 addNode 创建成功回调无条件回写原始 content；loadStructuredWorkspace 无本地编辑版本合并，直接 replaceSnapshot。实际 store + 延迟合成 HTTP 确认：新建后输入「新建后立即输入」，POST 迟到返回空串，内存正文变为空；reloadWorkspace 请求期间输入「刷新请求期间输入」，旧列表返回后变为「旧远端正文」。单篇 setSelectedFileId 的既有归属保护仍通过，不能覆盖这两条路径。建议为所有回写核对账号 / 节点 / 编辑版本，刷新合并干净字段，脏正文保留；创建确认前后要有明确生命周期，不直接拿旧响应覆盖编辑器。
2. **按笔记管理自动保存任务和状态（新增 UI-32）。** scheduleNoteSave 共用一个 noteSaveTimer，编辑 B 会清掉 A 的 700ms 待保存任务。模拟「编辑 A → 切 B → 立即编辑 B」后，仅有 B 的 PUT，A 新正文仍在本地，不代表已存到服务器。另测 A 的 PUT 延迟返回时，B 还未发 PUT，全局 noteSaveState 已变 saved。建议逐篇合并保存任务与状态，按版本确认，切换前安排保存但不阻塞导航；旧请求不能把另一篇或更晚输入标为已保存。不要通过放弃本地日志来减少成本。
3. **让失败可见且有下一步（新增 UI-33）。** NoteEditor 算出 saveLabel，但 JSX 未使用；workspaceError 只被 store / selector 保存，没有 App / DirectoryTree 消费；正文文件粘贴 / 拖入上传的 catch 直接吞错。建议正常成功保持安静，仅在异常 / 离线时显示正文附近轻提示，并提供明确的重试 / 同步入口；新建 / 重命名 / 移动等乐观操作失败应标注未同步或安全回退，不悄悄留下“看似完成”的状态。不要新增长驻状态栏或把技术错误堆满正文。

以上是已确认代码 / 隔离运行风险，不宣称用户某篇真实笔记已经丢失或服务器已被覆盖。本地日志是现有缓解，不等同于服务端保存和重载一致性保证。

### 第二轮：有价值的功能补齐（建议，不是已发生故障）

4. **把历史版本接回轻量入口（UI-21）。** VersionHistoryPanel / restoreNoteVersion 已有，但 versionHistoryOpen 只初始化 / 设置 false，没有设置 true 的路径；当前正文显示菜单只有章节编号。可以在文档更多菜单加「版本历史」，先预览、再确认恢复；必须先保护未保存输入并协调保存队列，不能只接按钮就宣布恢复安全。
5. **阅读章节跟随滚动（UI-31）。** 当前 activeHeadingId 基于编辑选区，不是正在阅读的位置。章节导航的展开 / 滚轮布局已优化，但单纯滚正文不会按可见章节切换标记。建议独立维护阅读章节（与 AI 编辑章节上下文分开），用正文实际滚动容器的观察器 / 帧节流更新，避免滚动时全文扫描或抢光标。
6. **标题编辑减少请求。** 当前标题 input 每次 onChange 调用 updateNodeName，笔记重命名被串行排队但不合并，暂时空输入也会提交「未命名笔记」。建议本地草稿即时显示，输入法结束 + 停顿或失焦后合并提交最新名称，并清楚处理失败。已确认调用路径，未做真实网络耗时 / 请求压测；不能把串行队列简单当成并行接口故障。
7. **离线搜索与设置状态一致性。** 搜索已有范围、取消过期请求与失败重试，不需要重做。可在未联网时搜索本地缓存，明确范围 / 排序并保留正文定位；目前 LibrarySearchDialog 仅调用服务器 literal search，这是新增能力建议。记忆开关则有旧 AI-06 缺陷：503 后服务内存与 localStorage 保留失败的新值，本轮隔离验证重新确认；应先修失败回退与迟到请求归属，不只恢复按钮外观。

本轮复跑既有 `test:note-open-race`（9）、`test:local-note-journal`（17 次输入单键持久化）、`test:offline-conflict`、`test:draft-lifecycle` 与 `test:chat-presentation` 均通过。它们不覆盖新增四条正文回写 / 调度风险。源码确认历史入口不可达与失败反馈未渲染；实际 IAB 只读 DOM 看到一个正文编辑器、显示设置入口、没有正文 status / alert，未注入失败或点击恢复。未进行生产写入、弱网实机、账号切换全链路或真实 AI 生成验收；已有安全审查问题也没有在本轮修复。

新增问题状态为未解决，既有条目不提高完成度；详细证据归并在开发问题汇总 UI-30 / UI-32 / UI-33 / UI-21 / UI-31 / AI-06。建议逐模块确认后实施并各自提交，不趁审查扩大视觉改版。
