# 草稿卡片阶段与正文补充实施

日期：2026-10-20；关联 AI-12；提交主题：`feat: 精简草稿卡片并衔接正文补充要求`。

## 产品行为

初次生成前，卡片直接展示可编辑标题与选填要求，不再堆叠标签、分割线和按钮底栏。标题是主要视觉内容，要求按输入长度伸展；简短说明在输入要求时出现，其位置预留以避免按钮移动。生成失败保留字段并可重试，生成中使用提交快照并阻止重复请求。

生成成功后，同一张卡片收成只读摘要与「打开草稿」。刷新恢复期间按钮等待数据就绪；正文生成中仍能打开工作台查看。生成后的卡片不再换主题或重新提交需求，已有 generationBrief 的后端接口也拒绝变更原任务。主题变化应创建另一份草稿，当前改动不新增历史草稿切换器。

工作台保留目录调整入口；原「全文要求」改为「正文补充要求」，上方只读显示最初要求，下方补充正文写法。手机也可访问该入口，弹层有关闭入口、有限高度和滚动边界。保存只用于后续正文，若要改已有内容则显式点击重写并确认。清空补充不改变最初要求，重新规划同一大纲也不会再自动清空补充。

生成时，两部分一起传入前台单节、后台作者和后台复核。明确修改相同条件时，正文采用这次补充；本章单独要求优先。补充要求不自动改变当前主题或大纲结构。此优先规则通过提示传递，真实模型是否遵循仍需质量验收。

## 边界与回滚

本轮不证明真实模型教案质量、多轮主题判定或 PostgreSQL 并发锁行为。未提交的初始卡片输入仍在内存；草稿写入与 checkpoint 绑定尚非跨服务单事务。历史任务沿用现有会话恢复，不承诺任意旧卡片直接切换工作台。已有正文需要用户确认才替换，失败保留验证针对已覆盖的模型 / 写入 / 图初始化路径，不泛化为所有网络时序。
