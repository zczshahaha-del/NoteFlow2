# 双字段草稿卡片实施记录

日期：2026-10-20；问题：AI-12。主题：`feat: 落实双字段草稿卡片与生成需求契约`。

## 本轮范围

沿用已批准的第一款「轻纸一体」：可直接编辑标题、选填要求；主按钮无箭头，无「先看大纲，再生成正文」说明。真正点击后才调用大纲生成，不把预览当功能完成。其余聊天范围入口、登录、记忆架构和笔记编辑器不在本轮改动范围。

## 实现与数据边界

- `DraftBriefCard` 使用真实输入、状态与回调；标题为空有提示，Enter 移至要求，输入法合成不提交，历史卡片只读。生成中锁定快照，已有大纲修改不自动重写；已有正文替换需确认。
- `draftBrief.ts` 与后端 `draft_brief.py` 明确区分原始请求和当前标题 / 要求。原始请求供来源核对，当前字段优先，清空的要求不能从原话重新回填。后端规划不擅自补年级 / 课时，标题保留作品名标点和文档形式。
- `agent.py` 保存原消息，而非以模型需求摘要覆盖；卡片、checkpoint、draft_config 持久化确认快照。前台单节与后台作者 / 复核均消费同一份确认需求，去除后台只写技术课程的角色限制。
- workspace 只在显式命令后生成；兼容没有新 manualOutline 标记的历史卡片，不因恢复 / StrictMode / 热更新自动生成。store、请求引用阻止本地重复提交。
- 重生成成功后才替换已有内容。PUT 按账号锁定草稿，生成中 / 已保存 / 已取消拒绝；重建图失败时回滚草稿修改。新建草稿沿用既有接口，不新增表或迁移。

## 未验收与恢复方式

- 不调用真实模型、不重新发送用户原消息、不操作真实账号草稿或记忆。模型能否准确理解任意自然语言、真实教案质量与多轮补充仍需单独验收，AI-12 为部分解决。
- SQLite 不证明 PostgreSQL 行锁并发行为；当前防重复主要覆盖同一客户端。没有新增服务器幂等令牌或跨设备任务协调。
- 未提交的卡片输入在内存中，刷新不保证恢复。点击后确认字段可持久化，但草稿写入与 checkpoint 绑定不是跨服务原子事务；若后者失败，会展示错误并保留本地草稿，刷新恢复仍有限制。
- 复用已有图初始化，不增加分布式事务 / 孤立图清理；失败未引用的图需沿用后续清理策略。
- 回滚应使用本轮提交的 `git revert`，不重置用户工作区、不删除笔记。新增 draft_config 字段为可选、旧代码忽略，不回滚数据库或用户内容。
