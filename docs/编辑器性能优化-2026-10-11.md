# 正文编辑器性能优化（2026-10-11）

范围：按用户「性能优化上去」及代码工具栏 / 文档显示设置截图，保留现有界面、配色、入口和即时保存，减少正文编辑器重复工作。未修改用户笔记、API Key、模型、后端、数据库、聊天 SSE、存储格式或保存防抖时间。

## 确认的开销与处理

1. 原 NoteEditor 的 `shouldRerenderOnTransaction:true` 使选区变化也刷新整个 React 编辑器；每次刷新都会遍历全文标题、重算编号、创建位置映射，再遍历标题 DOM。改为文档引用 / 当前章节选择性订阅，同章节内移动光标无需重绘整篇；选中文字工具条单独订阅格式状态，原位置、按钮、功能不变。此方式与 [Tiptap 官方性能指南](https://tiptap.dev/docs/guides/performance) 的选择性订阅建议一致。
2. 原每次输入在 onUpdate 转一次 Markdown，store 回传内容后的同步 effect 又转一次。新增每个编辑器只保留最近一次文档 / Markdown 的 WeakMap 缓存；同一不可变文档只转换一次，文本 / 格式 / 外部替换都按新文档失效。每次输入仍立即调用原 updateFileContent，不延迟本地持久化，也不改变服务器保存语义。
3. 标题列表和编号按不可变文档弱引用缓存，组件与编辑器插件共用；菜单、焦点与其他 UI 状态不重新扫描全文。当前文档改变后仍完整扫描一次，未宣称增量维护所有标题。
4. 原 React effect 直接写标题 DOM 的 data-heading-number，这些展示属性不归 ProseMirror 管理；后续 view 更新可以覆盖。基线新增标题后编号缺失，延迟到动画帧写入也不能稳定解决。改用编辑器节点 Decoration 与非历史 meta：编号仍仅显示，不写进标题文本 / JSON / Markdown / 导出 HTML；编辑、撤销、内容替换都会刷新。菜单切换只更新展示，不触发保存或产生撤销步骤。
5. 上轮代码高亮的弱引用缓存保持不变：编辑普通段落、移动光标和开合显示菜单不会重解析 20 个未变代码块。没有删减语言、颜色或复制能力。

## 实际对照

正式 NoteEditor / Tiptap 与构建后的生产 CSS，独立 Edge 无头浏览器，StrictMode，合成 23,500 个 UTF-16 字符、80 个二级标题、20 个 Go 代码块。所有请求中止、剪贴板为内存替身，不访问真实页面会话或真实笔记。

基线组件 / 扩展取自 `7a8d380`；优化结果来自本轮代码。分别以原生键盘在同一章节内移动光标 40 次、原生点击 / Tab / Escape 开合菜单 5 次，以及连续键入 `performance-check`（17 字符）计数。

| 动作 / 指标 | 1280px 基线 → 优化 | 320px 基线 → 优化 |
| --- | --- | --- |
| 移动光标：整个 NoteEditor 重绘 | 1 → 0 | 7 → 0 |
| 移动光标：全文标题扫描 / 编号计算 | 1 / 1 → 0 / 0 | 7 / 7 → 0 / 0 |
| 5 次菜单开合：全文标题扫描 / 编号计算 | 11 / 11 → 0 / 0 | 11 / 11 → 0 / 0 |
| 输入 17 字符：全文 Markdown 转换 | 34 → 17 | 34 → 17 |
| 输入 17 字符：即时更新保存调用 | 17 → 17 | 17 → 17 |
| 上述动作：未变代码块重新解析 | 0 → 0 | 0 → 0 |
| 新增标题的显示编号刷新 | 缺失 → 正确 81. | 缺失 → 正确 81. |

菜单本身仍需开 / 关重绘，优化后各 10 次；输入仍需更新显示，优化后 17 次。标题显示输出原为 React DOM 重写，现为每个新文档生成一份节点装饰，不能把两者称为相同的直接 DOM 写入计数。计数均为该夹具结果，React 批处理会使光标基线重绘次数有波动：先前一轮为 11 / 13 次，最终复跑为 1 / 7 次；优化后均为 0。

最终对照的 Markdown 转换累计时间约 73.1 → 39.4ms / 72.3 → 37.7ms，仅表示本次本机计时。脚本 wallMs 包含浏览器自动化、动作间调度和动画，不是输入延迟、FPS 或真实网络耗时，不能据此宣称全产品快了某一倍。最终基线 / 优化用例输出分别为临时目录 `noteflow-editor-perf-94J7Fs` / `noteflow-editor-perf-auwHpE` 中的 results.json；临时产物不作为永久依赖，断言和夹具在仓库可复跑。

## 限制与回退

本轮为 UI-27 部分解决，不代表任意大文件、真实三栏手感或全站性能验收。没有测实体输入法 / 触屏、Safari / Firefox、系统剪贴板权限、低配置设备、内存长期走势、服务器写入或提供商首字速度；这些保持待验证。原本同步本地快照保存和全文 Markdown 转换仍存在，只减少同一文档的重复工作，不以延后落盘换速度。

自动语言识别歧义与未支持语言仍按 UI-26 的限制处理；DEV-11 的构建弃用警告、既有安全 / 登录 / SSE 问题不由本轮解决。回退应针对本轮 `perf: 减少正文编辑器重复计算并稳定章节编号` 使用 Git revert，保留前一轮自动语法高亮，不用 reset 覆盖其他用户改动。
