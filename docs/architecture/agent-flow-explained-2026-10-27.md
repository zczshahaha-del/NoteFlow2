# NoteFlow 当前 Agent 全链路分支图解

日期：2026-10-27（Asia/Shanghai）。核对基线：`b3ba7b3`。

本文解释当前源码中的执行路径，帮助逐步理解 Agent。它不是未来重构方案，不意味着所有中文表达都已完成真实模型或生产端到端验收。图按正常的新请求展开；已有澄清等待时，优先续接原澄清。按钮入口、聊天入口、模型理解和程序校验分别标识。

## 1. 先认清三个不同的决定

| 决定 | 谁提供 / 判断 | 例子 |
| --- | --- | --- |
| 本轮使用什么模式 | 用户在输入框选择，后端强制约束 | 对话、全库搜索 |
| 想完成什么事情 | 对话模式由模型 Planner 理解，再经程序校验 | 回答、创建笔记、修改笔记、管理记忆 |
| 要参考哪些资料 | 页面提供可用信息，Planner 选择来源，实际服务再读取 | 选中文字、当前笔记、相关记忆 |

选中文字不会自动等于修改文字；打开一篇笔记不会自动等于每次都读取全文；发送当前正文不等于回答模型已经使用正文。

## 2. 从界面到 Agent 的完整入口

```mermaid
flowchart TD
    S[用户准备发起操作] --> Entry{从哪里发起}
    Entry -->|聊天框发送| Pack[携带问题、模式、近期聊天和页面状态]
    Entry -->|选区工具栏 AI 改一下| Quick[直接进入选区快捷改写，见第 7 节]
    Entry -->|草稿或修改预览中的按钮| Command[调用对应业务接口，见第 5、6 节]
    Pack --> Access[验证登录与聊天入口限流]
    Access --> Run[建立本轮运行记录]
    Run --> Waiting{同一会话是否在等待澄清}
    Waiting -->|是| Resume[把本次消息作为原请求的补充]
    Waiting -->|否| Mode{本轮模式}
    Mode -->|对话| Planner[模型提出计划：做什么、参考什么]
    Mode -->|全库搜索| Fixed[程序固定为全库检索问答，跳过模型意图规划]
    Planner --> Validate[程序校验计划]
    Fixed --> Validate
    Resume --> Validate
    Validate --> Decision{校验结果}
    Decision -->|缺少必要字段| Ask[返回追问、保存等待位置]
    Ask -->|用户补充| Resume
    Decision -->|确实无法判断| Unknown[说明未确定需求，请用户具体描述]
    Decision -->|模型调用或格式修复失败| Error[返回规划错误，不继续执行]
    Decision -->|可执行| Execute[进入回答、草稿、修改或记忆流程]
```

Planner 使用问题、近期聊天、当前笔记 ID，以及选中文字的受限片段理解请求。当前提示中的选区预览最多 320 个清理后的字符；实际选区问答可另行使用请求携带的选区文本。近期聊天是截取与限长后的内容，不等于自动检索全部聊天历史。

模式约束比模型的来源建议更强：`chat` 会剔除 `knowledge_base`；`ask_notes` 会强制只保留 `knowledge_base` 并转成问答。全库模式下即使问题措辞像创建 / 修改，也不会通过此入口分派到正式写入流程。

已知问题 AI-17：前端生成 `contextScope`，但当前后端只在 schema 中接收它，没有用于正式规划与校验。图不能把界面“引用当前笔记 / 移除引用”画成已实现的强制读取边界。

## 3. 对话模式：选择动作之后，才决定如何读取资料

```mermaid
flowchart TD
    Chat[对话模式] --> Plan[模型理解需求并提出计划]
    Plan --> Check{必要信息是否齐全}
    Check -->|不齐全| Clarify[追问主题、目标笔记或修改要求]
    Check -->|齐全| Intent{本轮要做什么}
    Intent -->|回答、解释、总结| Read[进入只读回答流程]
    Intent -->|创建新笔记| Draft[显示标题和要求卡片，见第 5 节]
    Intent -->|修改笔记| Edit[定位修改范围，见第 6 节]
    Intent -->|管理个人记忆| Memory[执行记忆操作，见第 8 节]
    Read --> Source{计划是否选择了笔记或选区来源}
    Source -->|没有| General[问题、近期聊天及本轮允许的记忆 → 模型回答]
    Source -->|有| Selection{是否选择了非空选中文字}
    Selection -->|是| Transient[直接把选区作为本轮资料]
    Selection -->|否| Current{是否选择当前笔记且存在笔记 ID}
    Current -->|是，存在未保存内容| Unsaved[使用请求携带的当前编辑器正文]
    Current -->|是，正文已保存| Indexed[限定当前笔记，检索相关已索引片段]
    Transient --> Answer[模型结合资料回答]
    Unsaved --> Answer
    Indexed --> Answer
```

图中的“选择来源”是最终校验后的 `context_sources`，不能只看页面是否高亮文字。若 Planner 同时选择选区与当前笔记，且当前笔记 dirty，则本轮资料可以同时包含选区和未保存正文；存在这类现场正文时，RAG service 直接返回现场资料，不再走索引检索。

对当前笔记的已保存内容，当前回答链路通常检索其中的相关片段，不保证将全文送给模型。“总结整篇”的质量不能仅凭识别到 current_note 就认定已覆盖全文。

对话中的普通回答可以读取已启用且计划要求的相关记忆；进入笔记 / 选区问答时，当前只读图会跳过长期记忆召回。参考笔记与记忆是不同来源，不能笼统理解成全部每轮都读取。

## 4. 全库搜索：固定走自己的笔记库检索

```mermaid
flowchart TD
    Mode[选择全库搜索并发送问题] --> Plan[程序固定计划：检索本人笔记库]
    Plan --> Sources[不把当前选区或未保存正文作为独立回答资料]
    Sources --> Retrieve[权限范围内检索已索引的笔记片段]
    Retrieve --> Channels[标题、词项、向量召回，融合后按配置重排]
    Channels --> Found{有可用来源吗}
    Found -->|有| Context[组织片段与来源编号]
    Context --> Answer[调用模型，按笔记证据回答]
    Answer --> Validate[检查引用编号并返回答案与来源]
    Found -->|没有| Empty[直接回复未找到相关笔记内容]
```

“全库”指当前账号可访问的笔记库，不是互联网；检索相关片段，不是把所有笔记全文拼进一次模型请求。打开着的笔记仍可能作为库中的正常命中出现，但不会限定只搜索这一篇。

全库模式强制 `context_sources=[knowledge_base]`。选中文字仍可能随前端请求发送，但不会作为这个模式的独立选区上下文；未保存正文不会通过该路径替换库内索引。即使已经保存，后台索引完成前也可能尚未参与新内容检索。当前全库模式不读取或隐式写入个人长期记忆，回答仍会接收近期聊天。

| 输入情况 | 当前源码处理 |
| --- | --- |
| 对话 + 未选中文字 + 普通问题 | 可以按通用问题回答，不自动检索全库 |
| 对话 + 未选中文字 + 明确问当前笔记 | Planner 选择 current_note 后，使用未保存正文或限定单篇检索 |
| 对话 + 选中文字并加入对话 + 解释这段 | Planner 选择 selected_text 后，使用选区资料回答 |
| 对话 + 选中文字并加入对话 + 修改这段 | Planner 判断修改后，进入修改预览；仍需实际范围检查 |
| 全库搜索 + 未选中文字 | 按问题检索笔记库后回答 |
| 全库搜索 + 已附选中文字 | 仍走全库检索，选区不是硬限制或独立资料 |

以上含模型理解的行是对应计划执行时的路径，不是对任意中文表达的百分之百成功承诺。

## 5. 创建笔记：聊天受理与正文完成是两段工作

```mermaid
flowchart TD
    Request[对话中请求创建笔记] --> Plan[提炼标题与明确要求]
    Plan --> Topic{是否有主题}
    Topic -->|没有| Ask[询问要写什么主题]
    Topic -->|有| Card[展示可编辑的标题和要求卡片]
    Card --> Click[用户点击开始生成]
    Click --> Outline[调用大纲生成并建立草稿]
    Outline --> Review[用户查看或调整大纲]
    Review --> Body[生成单节或启动后台批量生成]
    Body --> Result{生成结果}
    Result -->|部分失败| Retry[保留已有内容，处理或重试失败部分]
    Retry --> Body
    Result -->|用户停止| Stop[请求停止，保留已有章节内容]
    Result -->|可继续审阅| Edit[查看、编辑与组装草稿]
    Stop --> Edit
    Edit --> Decision{是否保存到笔记}
    Decision -->|暂不保存| Keep[保留草稿继续处理]
    Decision -->|确认保存| Save[创建正式笔记与版本，安排索引]
```

返回创建卡片时，本轮聊天 run 可以已完成，但草稿可能还没建立或正文尚未生成。大纲、章节、批量生成、组装和保存通过专门接口推进。草稿状态保存在业务表，LangGraph 配合维护流程检查点；不能把所有业务和模型调用都画成仅由一个图节点自动完成。

## 6. 修改笔记：定位范围、预览、再决定提交

```mermaid
flowchart TD
    Start[对话被理解为修改笔记] --> Note{是否打开了目标笔记}
    Note -->|没有| AskNote[询问或要求先打开目标笔记]
    Note -->|有| Scope[根据明确要求、选区和章节确定修改范围]
    Scope --> Target{范围能否确定}
    Target -->|明确整篇| Whole[取整篇正文]
    Target -->|明确章节| Section[定位指定章节，必要时用选区定位所在章节]
    Target -->|普通局部修改且有选区| Selection[定位选中的原文]
    Target -->|不清楚或匹配有歧义| AskScope[提示选择文字或说明章节、整篇]
    Whole --> Preview[生成并保存修改预览]
    Section --> Preview
    Selection --> Preview
    Preview --> Choice{用户操作}
    Choice -->|继续修改| Revise[基于当前预览生成修订]
    Revise --> Preview
    Choice -->|取消| Cancel[取消预览]
    Choice -->|应用| Check[检查原文和版本是否允许应用]
    Check -->|冲突或失败| Error[提示问题并保留处理入口]
    Check -->|通过| Save[应用修改，保存版本并更新索引状态]
```

没有选中文字不会自动等于修改整篇。当前范围解析会使用明确整篇 / 章节措辞、已附选区、明确章节定位；只是在阅读某一节，不代表授权修改那一节。措辞明确要求整篇或整节时，即使有选区，也可以按明确范围处理。

聊天修改入口会通过工具事件通知前端，再由前端同步相关笔记并调用创建预览接口，因此“聊天说正在生成修改预览”和“预览已成功生成”是不同阶段。自然语言“应用吧 / 取消 / 继续修改”还受 AI-13 限制；不能用旧执行分支的存在证明当前规划入口能到达它们。对应按钮和接口仍有独立能力。

## 7. 选中文字：两个入口必须分开理解

```mermaid
flowchart TD
    Select[在编辑器选中文字] --> Action{接着做了什么}
    Action -->|仅选中，没有添加操作| Local[只是编辑器选区，聊天不自动附带这段]
    Action -->|加入对话| Attach[聊天框出现选区引用]
    Attach --> Send[随下一条消息发送，再按对话或全库模式处理]
    Action -->|AI 改一下| Quick[专用选区改写接口：直接确定为局部修改]
    Quick --> Draft[返回候选文字，可继续调整]
    Draft --> Adopt{用户决定}
    Adopt -->|取消| Cancel[关闭本次改写]
    Adopt -->|采用| Current{原选区和编辑状态是否仍匹配}
    Current -->|匹配| Apply[替换编辑器选区，随后沿普通保存流程保存]
    Current -->|已变化| Reject[拒绝采用，提示重新选择]
```

快捷改写不先经过聊天 TurnPlanner，也不创建同一套持久修改预览；它使用编辑器选区快照，支持编辑器撤销。两种入口的取消、保存和恢复语义不能混为一谈。

## 8. 记忆：读取、显式管理、隐式提取是三件事

```mermaid
flowchart TD
    Input[本轮消息] --> Kind{哪种记忆用途}
    Kind -->|普通回答需要参考记忆| Read[对话计划选择记忆且开关允许时召回]
    Kind -->|明确要求记住、查看、修改、忘记| Manage[对话 Planner 选择记忆管理]
    Manage --> Enabled{记忆是否开启}
    Enabled -->|关闭| Disabled[说明记忆关闭]
    Enabled -->|开启| CRUD[调用记忆读取、保存、更新、删除或关闭工具]
    CRUD --> Result[按工具实际结果组织回复]
    Kind -->|用户自然提到可能长期有用的信息| Extract[普通任务成功后，由 MemoryWriter 判断候选]
    Extract --> Policy[检查主体、稳定性、敏感性、重复与冲突]
    Policy -->|合格且允许| Store[写主库并通过 Outbox 同步派生索引]
    Policy -->|不合格或提取失败| Skip[跳过隐式写入]
```

当前只读图在回答之后、finalize 之前等待隐式提取；不能把索引 Outbox 异步等同于提取已移到后台。普通问候也不是每次必读基础称呼，仍关联 AI-10 / AI-11。显式记忆结果成功后再组织回复，隐式提取失败原则上不应把已成功的普通回答变成失败。

## 9. 停止、重试、澄清和恢复

| 情况 | 当前处理与边界 |
| --- | --- |
| Planner 首次输出格式不合格或低置信度 | 有限进行一次修复请求；仍失败返回 planner_failed，不能当作语义 unknown |
| 缺必要主题 / 目标 / 修改要求 | 保存澄清等待位置；同会话下一条消息用于补充原计划；澄清期间有明确取消处理 |
| 普通回答失败 | 保留已显示部分和错误；符合条件时用原请求快照重试；有活动草稿 / 预览等情况不开放普通回答重试 |
| 回答重试 | 后端 retryAnswerOnly 防止重放写操作，并抑制隐式记忆写入；不是重试整个业务任务 |
| 点击聊天停止 | 前端取消读取并请求取消 run / 等待 checkpoint；不能据此保证外部模型瞬时停止或已计费调用撤回 |
| 点击草稿停止生成 | 走独立的草稿停止接口，设置取消请求、取消活动生成、保留已有正文 |
| 预览应用 / 取消 / 修订 | 通过预览按钮与专用接口执行；与聊天停止不同 |
| 返回历史会话 / 工作区 | 读取持久聊天、草稿、预览与相关 checkpoint；已有恢复基础不代表全部多轮自然语言续接已验收 |
| 直接输入“继续 / 应用吧 / 取消刚才的” | 旧业务分支存在，但正式 TurnPlan 映射未接通对应意图，沿用 AI-13；不要画成已可靠可达 |

## 10. 不同层保存了什么

```mermaid
flowchart LR
    A[对话原话与回答] --> History[聊天历史：说过什么]
    B[运行和步骤记录] --> Runs[本轮执行：做了什么]
    C[LangGraph 检查点] --> Position[图流程：暂停在哪里]
    D[业务 checkpoint] --> Binding[工作产物绑定：草稿或预览在哪里]
    E[草稿与预览业务表] --> Artifact[候选内容：实际生成了什么]
    F[正式笔记与版本] --> Saved[确认后的内容：保存了什么]
    G[长期记忆主库及派生索引] --> Memory[跨会话背景：允许记住什么]
```

这些记录关联使用，不能认为“聊天结束”就代表“整篇正文生成完成”，也不能把聊天历史、图检查点、正式笔记或长期记忆当作同一种数据。
