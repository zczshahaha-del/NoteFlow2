# NoteFlow 侧栏统一状态提案

> 2026-10-01。用户批准先制作侧栏状态对照图；只交付设计，不修改正式 UI。当前状态：待用户评审。

## 范围与视觉方向

本轮采用可交互的状态可视化稿，再由浏览器导出完整图片。它让第一层菜单和深层表单一起接受评审，不以一张菜单外壳代表全部点击体验。

- 侧栏桌面展示宽度仍为 260px；目录、收起、新建、搜索、笔记层级和底栏入口顺序保留。
- 柔白侧栏与白色弹层分工；中性悬停与淡蓝灰选中区分，不给每个动作加饱和蓝色。
- 主要目录 / 菜单文字统一为 14px；底栏身份文字 13px，次级信息 11–12px；所有字号在本稿内显式定义，不沿用正式页面的样式覆盖问题。
- 控件行高默认 38px，菜单统一 14px 圆角、细线 Lucide 图标、轻阴影和 170ms 入场反馈；支持减少动态效果。
- 邮箱表单与设备列表直接放在弹层内容流中，移除额外的外框套外框；输入框保留必要边界，危险操作仍使用文字和低饱和红色区分。
- 账号头像降低饱和度；回收站非空指示仍保留，只收敛视觉，不擅自删除状态信息。

图片里的圆角标本外框、点阵背景和状态标题仅用于设计评审，不提议把正式侧栏改成悬浮卡片或新增产品导航。示例设备、时间、地址和邮箱均为脱敏展示，不来自用户会话数据。

## 八种可对照状态

1. 目录默认；
2. Redis 选中与另一个条目悬停；
3. 新建菜单展开：新建笔记、新建文件夹；
4. 笔记操作展开：重命名、移动到、导出、置顶、收藏、删除；
5. 账号向上展开：登录邮箱、登录设备、退出登录；
6. 登录邮箱输入；
7. 邮箱验证码输入与确认并绑定；
8. 登录设备展开：有效会话、刷新、设备状态和退出。

映射依据为既有功能审计及本轮直接核对的 `DirectoryTree.tsx` / `AppNav.tsx` 菜单与账号内容。未增加最近使用、固定收藏分区、品牌栏、统计、同步状态等不存在的入口。

## 后续评审：图标仍缺少精修感

用户提供三张局部截图，将反馈聚焦到收起目录、新建、搜索、文件夹箭头、账号箭头、回收站及设置：这些符号看起来简陋、粗糙，缺少美感。该反馈不表示已经批准正式实施，也不等于用户否定全部布局；本轮先诊断并记录，不改源稿或正式 UI。

证据：源稿多数图标共用 17px 画布与 1.6 的笔画设置，两个单箭头另缩到 12px；收起使用 `chevrons-left`，回收站使用 `trash-2`，设置使用 `settings-2`。这些是规范图标库里的图形，不是随手乱画；问题在于选型、不同轮廓的视觉重量以及小尺寸细节没有单独调校。统一外接框尺寸与线宽不能自动得到统一的视觉重量。

设计判断：双箭头显得局促，加号与搜索环的显眼程度不一致，垃圾桶的内部竖线在小尺寸下偏密，设置的调节滑杆形态与用户期待的精致控件感不一致。上述为结合截图的视觉评审，不将它们描述为已测得的像素渲染错误；放大截图不能证明源 SVG 存在分辨率缺陷。

建议下一轮只做这些图标的原样 / 精修对照：校准轮廓、笔画、端点、内部留白和视觉中心；评估侧栏轮廓的收起图标、简化回收站内部线条及更清晰的设置图形；同时检查放大图与实际显示尺寸，不靠更细线条、渐变或外加按钮框替代精修。所有功能、入口和整体排版继续保留，具体候选尚未绘制或验证。

参考 [Apple SF Symbols](https://developer.apple.com/sf-symbols/) 对多档字重、尺度及文字对齐的设计说明，只参考视觉协调原则，不声称已经使用 Apple 图标，也不默认其资源可直接用于当前网页项目。此轮仅做截图、源稿和官方说明核对；UI-16 / UI-17 仍未完成审美验收。
