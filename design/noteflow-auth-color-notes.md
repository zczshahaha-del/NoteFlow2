# A 方案 · 主按钮颜色对照

设计日期：2026-10-08；外观确认：2026-10-09。用户在柔和蓝完整预览的确认问题后回复「是的」，确定采用 **A 的「柔和留白」布局 + 柔和蓝主按钮**。这是设计选择确认，不代表正式认证改造已实施或验收。

## 改动范围

源稿由上一轮 `noteflow-auth-entry.source.html` 派生。两种颜色均使用完全相同的 A 页面：品牌、排版、字体、输入、字段顺序、48px 按钮、12px 圆角、17px 箭头、账号流程与过渡不变。只改蓝色主按钮的默认 / 悬停 / 按下色和对应深色外观，不给输入、标签或辅助操作染蓝。原「轻盈聚焦」布局仍在历史稿中保留，本颜色稿不采用它。

用户指出原按钮视觉上就是黑色；本轮用「原深色」标示参考，不再用色值名否认其视觉感受。颜色是本轮唯一评审变量，不增加新布局候选。

浅色蓝按钮：默认 `#52769A`、悬停 `#496B8D`、按下 `#426384`，白字。对应对比度约 4.75 / 5.57 / 6.27。深色外观用浅雾蓝表面与深色文字，默认 / 悬停 / 按下约 7.41 / 8.89 / 6.16。不用强渐变、光晕或厚阴影；白色背景保持原样。

## 文件与验证

- `noteflow-auth-color.source.html` / `.preview.html`：完整 A 页面颜色对照；默认柔和蓝，可切换原深色，登录 / 注册交互仍为本地演示。
- `-login.png` / `-register.png`：蓝色完整桌面图；`-deep-login.png` / `-deep-register.png` 为原深色。
- `-mobile.png` / `-deep-mobile.png`：320px 完整图；`-dark.png` / `-deep-dark.png`：深色外观。
- `node design/verify-auth-entry.mjs --color`：复用认证稿检查，加蓝按钮颜色与文字对比度、悬停 / 按下检查。省略参数回归原稿。环境变量和离线浏览器启动权限与上一轮相同。

共享脚本仅增加设计选择参数，不改变真实认证接口。已知外壳同时声明 Floating UI Core / DOM，两者在测试中都继续被阻断，仅作为允许出现在阻断日志中的已知静态资源；没有放行外网。未知 URL 仍打印并使检查失败，DEV-20 原未知请求根因不因此宣称已解决。

两种颜色各实测 1024 / 736 / 320px；主按钮几何、输入 / 反馈位置、目的切换、倒计时、取消、焦点 / Enter、输入隐私、深色和减少动效通过。浅色桌面实际默认 / 悬停 / 按下颜色与对比度断言通过；深色默认颜色与对比度实测通过，其余深色色对按定义计算。新颜色稿及无参数的原稿完整检查均 ok:true、pageerror 为空；完整桌面、窄屏与深色图片人工检查无裁切。以上仅离线验证，不能代替正式账号或邮件 E2E。
