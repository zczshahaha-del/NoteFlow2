把零散的知识整理成清楚的路径。先理解每一步在做什么，再把代码串起来。

先抓住主线：建立连接、定义数据，然后读写记录。不必一次记住所有细节。

从一条记录开始

学习一个新工具时，可以先跑通最小的例子，再逐步补充条件。这样，代码和概念能够对应起来。

  • 这一条数据长什么样？
  • 我想对它做什么操作？
  • 执行之后，应该看到什么结果？
Go
type User struct {
    ID   uint
    Name string
}

user := User{Name: "Alice"}
db.Create(&user)

先观察这段最小示例，再继续整理后续操作。

让笔记有一条清晰的主线

不要只堆放代码。给每段示例补上一句用途，再说明它与上一段的关系，回头复习时就不必重新猜测。

把“做什么”和“为什么”放在一起

示例负责展示做法，正文负责解释选择。重要的提醒单独出现，但不需要给每一句话都加一个框。

一篇好读的笔记，应该让下一步很容易找到，也让已经理解的内容不再反复解释。

留一点空间，方便以后补充

遇到新的问题时，把它放回对应的章节。需要进一步解释的地方，可以带着当前笔记向右侧 AI 提问。

标题、列表、代码和提示各自有清楚的层级；阅读时，它们仍然属于同一篇笔记。
