# NoteFlow V8 · Precision Soft Workspace

> 状态：仅作为已确认的视觉语言参考，功能排版已由 V9 现有功能重排稿取代，不能进入正式实现。V7 因生成式位图出现文字、图标、间距和边缘变形，已停止作为候选方案。

## 这次先解决什么

V8 不再用图像模型“猜”复杂 UI，而是用真实 HTML/CSS、规则网格和同一套 Lucide 矢量图标搭建，再由浏览器确定性渲染为 PNG。这样可以保证：

- 文字基线、图标光学尺寸、列宽、间距和圆角都由代码精确控制；
- 同类按钮、状态、图标和表面使用同一套规则；
- 设计稿能直接检查悬停、按压、模式切换、AI 面板收起和响应式变化；
- 后续进入 React 实现时可以复用 Token 与布局逻辑，而不是从失真的图片反推代码。

## 已确认的审美约束

本稿继续执行用户确认的 `BBC + CBB`：

- 柔润、时尚，但不做糖果感或夸张发光；
- 按钮柔软圆润、轻微悬浮，按压时有小幅回弹；
- 可以优化现有功能的布局和交互表现，但不得凭空增加功能或改变产品逻辑；
- 主色为奶油白与雾蓝，文字使用暖墨色；
- 图标统一为细线，并只在选中或 AI 状态中使用局部浅填充；
- 信息密度维持均衡，不做过稀的展示页，也不做拥挤后台。

## 视觉系统

- 网格：顶栏和正文区都采用 `236px / flexible / 374px` 三段网格，横向边界完全一致。
- 圆角：工作区主表面默认 22px，图标按钮 11px，输入与分段控制 12–16px；不再随机变化。
- 图标：统一 15–18px 视觉尺寸和约 1.7px 线宽，默认无底框，交互态才出现浅色承载面。
- 阴影：只有品牌标记、主按钮、选区工具和 AI 输入层使用阴影，其余依靠色域与发丝线分层。
- 字体：标题采用偏编辑出版物的紧凑字距，正文使用宋体衬线阅读轴，控制文字使用无衬线体。
- 动效：统一 170–260ms 和 `cubic-bezier(.22, 1, .36, 1)`；位移控制在 1–22px，按压缩放不低于 0.96。

## 可交互与可调整项

> 以下交互只用于 V8 原型演示，其中无法在当前 NoteFlow 找到真实对应的部分不得带入下一稿或正式代码。

- AI 助手可从顶栏展开或从面板收起；中间编辑区随之扩展。
- AI 的问答、润色、行动三个模式可切换，当前模式和内容标题同步更新。
- 搜索、AI 输入、导航项、选区工具和按钮都有明确焦点或悬停反馈。
- 预览内提供圆角、AI 面板宽度、强调色和信息密度四个可调参数，用于下一轮快速收敛。
- 宽屏显示三层工作区；中屏把知识库压缩为图标轨；窄屏只保留编辑器主任务。

## 下一稿的功能真实性规则

1. 先从当前代码和真实界面提取功能清单，再开始排版；不从视觉构图反推产品功能。
2. 每个可见按钮、入口、状态、数字和模式都必须能关联到现有功能及触发逻辑，无法关联就删除。
3. 不增加“看起来完整”但实际不存在的快捷入口、统计数量、AI 模式、分享收藏或装饰性伪交互。
4. 对现有功能只做必要的层级、间距、尺寸、响应式和动效优化，不随意改名、合并、隐藏或改变工作流。
5. 如果发现值得新增的功能，只能写入独立建议清单，得到用户确认后才能进入设计稿。

## 当前边界

- 这是高保真设计与交互原型，尚未改动正式 React 业务组件。

- V8 只能作为视觉风格参考，其中的顶栏分组、导航组织、编辑器工具和 AI 模式均不能视为产品决策；必须基于现有 NoteFlow 功能重新梳理。
- 排版与功能动线逐项确认后，再按设计 Token、顶栏、知识库、编辑器、AI 面板和响应式分批实施并分别提交。
