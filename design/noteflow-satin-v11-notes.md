# NoteFlow V11 · 柔白原生工作台

> 日期：2026-10-01
>
> 状态：2026-10-01 用户退回，当前不采用为实施基线；不是已实施的新 UI。
>
> 范围：目录、正文、选区工具栏、章节导航、AI 对话与输入区，以及已有账号菜单。没有修改 `src/` 或真实数据。

## 评审结果与纠偏

用户反馈：改动太多，设计者没有充分理解细节，出现自行更改。保留功能名称和入口，并不等于保留原有布局、信息密度、显隐规则、触发条件及操作习惯；渲染检查通过也不等于设计符合产品要求。

本稿退回，不继续扩大整页方案，不作为代码实施依据。图片和原型保留为过程证据，不删除历史文件，也不回退未被修改的业务代码。后续以真实界面为基线，一次讨论一个区域，先做原样对照；布局、行为、可见性或文案变化必须单列并确认，审美方向认可不能代替逐项批准。

## 设计依据

用户已认可功能理解，进一步明确要求整个外观具有苹果式的精致、柔和与顺滑感，而非继续只调整功能排布。本稿沿用 [现有功能边界](noteflow-current-function-audit.md) 和已选侧栏 A，将整个主工作台放进同一套表面、文字、图标和控件语言中。

借鉴 [Apple 材质设计指南](https://developer.apple.com/design/human-interface-guidelines/materials) 的内容层与控制层区分、材质克制原则。本稿不复制苹果品牌、窗口交通灯、SF Symbols 或不存在的产品功能，也不把网页 CSS 渐变声称为原生 Liquid Glass。

## 相比 V10 的变化

- 基础配色改为柔白、石墨文字和中性灰，少量蓝色只承担选择、引用和发送动作；侧栏与 AI 不再同时铺大面积蓝灰色。
- 正文仍是无卡片阅读空间；标题、章节、正文和时间信息重新校准。宽屏正文建议 16px / 1.9，阅读宽度上限 660px。
- 选中文字按文字行轻高亮，不再包成大块圆角蓝色卡片；12 个既有选区操作全部保留。
- 新建按钮从高饱和实心蓝块改为轻量中性控件；发送仍明确突出，采用小圆形按钮。
- AI 回答连续排版；用户消息用中性灰区分，输入区用轻边框和柔和阴影建立操作层级。
- 账号区融入侧栏，头像使用浅蓝灰，菜单向上展开；只包含登录邮箱、已登录设备、退出登录。回收站和设置继续独立，未增加常驻通知点。
- 菜单、选区工具栏、输入区使用统一细边框、曲率和低强度阴影。悬停、按下和展开均有短反馈，并支持减少动态效果。

主要建议 Token：正文 `#fdfdfd`、侧栏 `#f3f3f5`、AI `#f7f8fa`、主文字 `#292a30`、正文 `#4b4d55`、辅助文字 `#777982`、关键蓝 `#397be7`。这些是浅色设计值；源稿以 `light-dark()` 提供对应深色值，但本轮没有完成深色视觉验收。

## 功能与尺寸边界

| 区域 | 对应现有实现 | 本稿的变化与限制 |
| --- | --- | --- |
| 目录、搜索、新建 | `DirectoryTree.tsx` | 保留原有入口；宽屏侧栏 260px，中屏建议 220px，不新增导航分区或常驻内联检索 |
| 账号、回收站、设置 | `AppNav.tsx` | 只有账号菜单绘制展开状态；设置、设备和邮箱详情仍需独立评审 |
| 标题、时间、正文、选区 | `NoteEditor.tsx` | 只有视觉与局部状态预览，没有接入编辑器保存、上传或链接写入 |
| AI、引用、上下文、模式 | `AIPanel.tsx` | 只保留对话 / 全库搜索；宽屏面板建议 416px，真实应用仍为原默认宽度和可拖拽逻辑 |
| 面板展开、收起与抽屉 | `App.tsx` | 保留现有工作流，原型窄屏为覆盖抽屉；正式实施还需验证正文宽度、拖拽和键盘焦点 |

五篇笔记和文件夹名来自用户已提供截图。Redis 正文、时间、AI 消息、引用位置与历史会话均为排版示例，不是读取用户笔记。其他笔记不填充 Redis 正文冒充内容。账号细节图是静态放大状态；交互应在完整预览中体验。

## 验证记录

本轮在浏览器中实际渲染并截图，未使用生成式图像模型绘制中文或图标。

| 检查项 | 证据与结果 |
| --- | --- |
| 完整主稿 | 1280px 实际浏览器视口，产品内容宽 1233px、无横向溢出；完整图为 1265×1077，目录底部和 AI 输入区均完整可见 |
| 专注阅读 | 收起 AI 后正文扩展，已有 AI 启动入口出现；专注图为 1265×1068，已目视检查 |
| 账号排版 | 修正中屏“我的账号”换行，标签高度 20px；展开菜单只有现有三项，Escape 可收起；260×258 放大图无溢出 |
| 1024px 内容视口 | 通过响应式夹具核实 iframe `innerWidth=1024`，产品内容宽 1009px；工具栏 392px ≤ 正文 399.32px，无横向溢出 |
| 320px 内容视口 | 通过夹具核实 `innerWidth=320`；正文 259px、工具栏 259px，无横向溢出。目录可开关，账号菜单右边界 236px；AI 面板内容宽 298px，无横向溢出 |
| 原有菜单 | 新建笔记 / 文件夹可见；显示设置可隐藏 / 恢复章节编号 |
| AI 局部交互 | 选区上下文可移除与添加；对话 / 全库搜索可切换；空输入时发送禁用 |
| 图标与脚本 | 主稿 73 个 SVG、未替换图标占位 0；账号放大图未替换占位 0；浏览器 error / warn 日志为空；源片段脚本语法检查通过 |
| 状态恢复 | 沿用 revision 防旧快照回流；增加设计身份与视口类型检查，防止其他稿件或不同断点快照误用 |

本轮浏览器视口覆盖工具调用后实际尺寸仍为 1280×720，因此没有把工具调用成功当作 1024 / 320px 验证。响应式夹具在 iframe 创建前设置真实内容视口，分别测量 `innerWidth` 和元素边界；这不等同于实体手机验证。该工具限制记录为 DEV-12。

本轮只涉及设计与文档，未运行正式应用构建、后端测试或业务 E2E，也未执行真实退出登录、发送、搜索或笔记写入。深色模式、可拖拽面板、草稿、修改预览、设置详情和真实交互链路仍待评审与实施，不能因本稿而标记已完成。
