Redis 是一个基于内存的键值数据库。它不仅能用来做缓存，也支持计数、排行榜和消息队列等常见场景。

1为什么这么快

它的高性能主要来自内存访问、紧凑的数据结构和高效的事件处理。理解 Redis 时，不应把“单线程”当作唯一答案，也需要区分命令执行与网络 I/O。

2常用数据类型

类型适合的场景
String缓存、计数器、简单的键值存储
Hash用户信息、商品属性等结构化数据
List消息列表、按顺序处理的数据
Set去重、共同关注、集合运算
Sorted Set排行榜、带权重的有序集合

3一个简单的缓存示例

为缓存设置合适的过期时间，避免数据一直占用内存。

SET user:1001:name "Alice" EX 3600
GET user:1001:name

能结合这段笔记，解释一下 Redis 的单线程和多线程 I/O 吗？

已引用 · Redis

可以把它们理解为两个不同的层次。

“处理命令”和“收发网络数据”并不是同一件事，所以两种说法并不矛盾。

  1. 01
    命令执行：主要串行处理

    常规命令主要在主线程执行，让数据结构的操作保持简单、可预测。

  2. 02
    网络 I/O：可以并行分担

    多线程 I/O 可分担网络数据的读写，不意味着所有命令都并行执行。

  3. 03
    性能：来自整条处理链路

    内存访问、数据结构、网络负载与命令复杂度，都影响实际响应速度。
