# AI 草稿窗口 · 柔和留白局部实施

日期：2026-10-03。用户看过整合稿后明确表示“可以修改”，本轮才进入正式组件；此前设计阶段没有修改业务界面。

## 范围

仅修改 `src/components/AIDraftWorkspace.tsx` 并新增作用域 `draft-workspace.css`。外部服务、模型、数据、其他工作台区域和共享 ConfirmDialog 源码不变。没有将合成 Redis 示例放进产品。

- 标题 / 目录 / 正文 / 底栏去掉重复框线，统一中性表面、文字层级与轻量动作。章节选中用整行浅底；真实编号、生成中、完成、未生成和失败语义保留。
- 顶部、目录管理、保存的已有图标关闭统一默认透明、18px / 1.8 Lucide X、10px 圆角，悬停才有淡底，140ms 色过渡，不旋转、缩放或弹跳；删除顶部原生 title，accessible name 保留。
- 一般动作图标 17px / 1.65；保存与提交保持主要动作，确认保持轻量成功色，停止 / 放弃仍有危险语义。按钮不再重复描边。
- 修改要求保持原底部位置和标签，无拖拽手柄。正式原 textarea 已是 resize:none，本轮新增输入自适应 52–104px、超过上限滚动、清空 / 切章复位；ResizeObserver 只对宽度变化重算，避免自身高度反馈循环。
- 目录管理、全文要求、保存保持已有入口 / 顺序 / 表单 / 回调 / 禁用条件，使用同一局部表面。进场 180ms，减少动效禁用动画；原关闭仍立即生效，不声称已实现退场或跨工作台协调动画。
- 不采用预览稿的 696px / 200px 缩小尺寸或手机工具栏换行。正式窗口最大 1240×880、桌面目录 282px、正文容器 820px，原 md 以下工具栏隐藏及目录 168px 高度保持。仅修改框在窄屏内部换行以容纳触屏文字，没有迁移入口。
- 草稿输入法 Escape 不误关；错误正文增加 alert 语义，键盘焦点可见。没有重写完整模态焦点管理或添加新业务按钮。

## 本轮确认的问题与局部处理

1. **深色旧样式覆盖（UI-05）**：旧 `bg-white` 会命中全局深色 `!important`，压过局部中性动作。移除本区域动作 / 字段的旧表面、字体、颜色类，改为作用域样式；不改全局 CSS 层叠。深色选择 / 主次动作 / 字段和表面重新取图检查，正式全局问题仍未解决。
2. **名义行高不等于实际目标（UI-05 / UI-17）**：`h-11` 基于 rem，全局 15px 下实际 41.25px，新增触屏最小高度断言失败。章节局部明确 44px，触屏图标 44×44、动作至少 44px、字段 16px；独立 320px 浏览器断言通过。
3. **嵌套确认被挡及 Escape 同时关闭父层（UI-11 / UI-17）**：目录层 z=130，原共享确认 z=120；草稿自己的 document Escape 监听同时响应。仅用草稿确认包装层将原确认提高至 140，确认存在时草稿监听不处理 Escape。合成“重做大纲”确认取消 / Escape 后目录仍在、未触发重做，层级断言通过。共享确认流程和其他消费者不变。

以上都属于本模块既有 UI / 状态问题的跟进，不新增同义 ID；正式页面实际 E2E 未验收，保留部分解决口径。

### 测试迭代说明

初版离线替身插件未设 `enforce:pre`，被 Vite 解析器抢先加载真实 selector，合成页面空白、恢复服务未调用。改为前置解析后进入正式组件和合成恢复，不修改产品 store。另初始测试误以为章节软删除有确认，源码核对后改测原软删除 / 恢复及真正存在的重做大纲确认，没有为测试新增删除步骤。减少动效的全局 `!important` 保留 0.01ms 时长，改验 animation-name=none，而不是错误要求时长字符串必须 0s。首次深色截图采样仍在颜色过渡中，加入结束等待后重生成；旧中间图片不作交付证据。
