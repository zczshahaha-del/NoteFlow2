# 登录与注册 · 柔和留白 A 正式实施

日期：2026-10-09。用户确认柔和蓝完整 A 稿，并明确同意落实到正式登录 / 注册页面。本轮仅改认证入口与必要认证链路，不重排工作台，不修改真实账号或笔记做测试。

## 外观与交互

正式 `LoginPage.tsx` 采用原稿的品牌位置、360px 表单、浅中性输入、12px 圆角、48px 主按钮与柔和蓝。图标同用 Lucide，18px / 1.65 线宽，主箭头 17px。登录 / 注册滑块 230ms；聚焦、悬停和按下为短过渡；尊重减少动效。清理已无消费者的旧 `.login-*` 宣传 / 预览样式，所有新颜色只作用于 `.auth-page`。

反馈保留稳定的 58px 区域，长错误可滚动，发送 / 错误 / 重试不推动主按钮。验证码与密码登录仍为现有能力，但方式入口放在主按钮下；注册只填邮箱和验证码。重设密码保留邮箱、验证码、新密码，完成后返回密码登录并聚焦密码字段。

等待中切换入口 / 改邮箱 / 手动输入验证码会 abort 发码请求并忽略迟到结果，不覆盖用户正在输入的验证码；取消等待不清除可能已经发出的邮件的冷却时间。冷却按邮箱与目的隔离，切换回来不会绕过。发码失败也保守保留 60 秒等待，后台的可配置间隔与前端默认值仍可能不同。提交认证时禁止重复提交或切换身份字段，不把无法撤销的服务端认证伪装为已取消。Enter 忽略输入法合成；失败保留当前输入。

## 正式接口与兼容边界

- `POST /api/auth/email-code/request`：`{ email, purpose: "login" | "register" }`；省略 purpose 仍按登录处理。两种验证码哈希、校验和重发限制互相隔离。
- `POST /api/auth/register`：改为 `{ email, code }`，必须通过注册用途验证码；不会预先创建用户、设置密码或发 Cookie。旧的邮箱 + 密码请求缺 code 返回 422，前后端需要一起更新。
- `POST /api/auth/email-code/confirm`：只登录已有账号，验证后发现无账号则返回 404，请用户注册；注册发现已验证账号则返回 409，请切换登录。账号存在性只在有效邮箱证明之后反馈。
- 旧未验证账号通过邮箱验证后保留原 user_id / displayName / 数据归属，清除未验证时留下的密码并撤销原 UserSession；新会话在同一事务签发。已验证账号的正常登录不清除密码或其他设备会话。
- 已验证账号的无 sid 历史 JWT 不再用于访问或迁移，需重新登录；未验证存量账号仍保留原兼容路径，**不是整个 SEC-02 已解决**。存量账号没有做批量改写或强制迁移。
- 无密码账号仍可通过既有邮箱重设密码流程设置密码；没有另外扩展账号设置页的密码入口。首次邮箱重设也执行安全认领。
- 不新增数据库字段 / 迁移。不改变验证码 HMAC、有效期、失败次数与公共限流；Webhook 增加注册类型并纠正重设类型，接收端需支持 `email_register_code` / `password_reset_code`。

本地浏览器不允许 localStorage 时，离线缓存只作为可选能力；不能把服务端已成功的 Cookie 认证变为页面失败。缓存访问包括 getter 判断均放入 try，关联 DEV-21。
